# Python Style Guide — Проект todo-cli

## Общая философия

Код должен быть простым, понятным и однозначным.
Предпочитаем функциональный стиль. Избегаем классов, если нет веской причины.

## Функции

- Каждая функция — **одна ответственность**.
- Размер: **не более 20–25 строк** (без пустых строк и docstring).
- Имя функции: **глагол или глагольная фраза**, описывающая действие.
  Пример: `add_task`, `load_tasks`, `mark_as_done`.
- Имя переменной: **существительное**, описывающее суть.
  Пример: `task_text`, `task_id`, `tasks_list`.

## Type Hints

- Обязательны для **аргументов** и **возвращаемого значения** функций.
- Пример:
  ```python
  def add_task(tasks: list[dict], text: str) -> list[dict]:
  ```

## Docstring

- Каждая функция должна иметь **docstring**.
- Формат: однострочный для простых, многострочный для сложных.
- Docstring описывает:
  - что делает функция,
  - какие аргументы принимает,
  - что возвращает.
- Пример:
  ```python
  def add_task(tasks: list[dict], text: str) -> list[dict]:
      """Добавить новую задачу в список.

      Args:
          tasks: Текущий список задач.
          text: Текст новой задачи.

      Returns:
          Обновлённый список задач.
      """
  ```

## Комментарии

- Писать **учебные поясняющие комментарии**.
- Объяснять **смысл и причину** решения, а не повторять код.
- Правильно:
  ```python
  # Генерируем ID на основе текущего времени,
  # чтобы избежать коллизий при последовательных вызовах
  task_id = int(time.time())
  ```
- Неправильно:
  ```python
  # Получаем текущее время
  task_id = int(time.time())
  ```

## Запреты

- Запрещены классы без обоснованной необходимости.
- Исключение: `dataclass` для простых структур данных (например, `models.py`).
- Запрещены глобальные изменяемые переменные.
- Запрещено использовать `from module import *`.

## Обработка ошибок

- Обрабатывать **ожидаемые ошибки** через `try/except`.
- Не глотать ошибки молча: логировать или выбрасывать с пояснением.
- Пример:
  ```python
  try:
      data = json.load(f)
  except json.JSONDecodeError:
      # Файл пуст или повреждён — начинаем с пустого списка
      data = []
  ```

## Тестирование

- После каждого изменения кода запускать:
  ```bash
  python -m unittest discover tests
  ```
- Тесты писать в стиле `unittest.TestCase`.
- Методы тестов называть `test_<что_проверяется>`.
- Лимит в 20–25 строк не применяется к методам тестов.
