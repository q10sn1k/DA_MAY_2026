## 2. Запуск MySQL через Docker Compose

### 2.1. Что такое Docker в этом занятии

Docker позволяет запустить MySQL в отдельном контейнере. Для слушателей это удобно: не нужно вручную устанавливать MySQL в систему, настраивать сервисы и искать конфигурационные файлы.

Простая схема:

```text
Ваш компьютер
   |
   | запускает
   v
Docker-контейнер
   |
   | внутри контейнера работает
   v
MySQL Server
```

---

## 3. Файл `docker-compose.yml`

Создайте файл `docker-compose.yml` в рабочей папке проекта.

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: mysql_container
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: testdb
      MYSQL_USER: testuser
      MYSQL_PASSWORD: testpass
    volumes:
      - mysql_data:/var/lib/mysql
    restart: unless-stopped

volumes:
  mysql_data:
```

### Разбор файла

| Строка | Что означает |
|---|---|
| `services` | Список сервисов, которые нужно запустить |
| `mysql` | Название сервиса |
| `image: mysql:8.0` | Используем готовый образ MySQL версии 8.0 |
| `container_name` | Имя контейнера, чтобы к нему было проще обращаться |
| `ports: "3306:3306"` | Открываем порт MySQL для подключения с компьютера |
| `MYSQL_ROOT_PASSWORD` | Пароль администратора MySQL |
| `MYSQL_DATABASE` | База, которая создастся автоматически при первом запуске |
| `MYSQL_USER` | Пользователь, который создастся автоматически |
| `MYSQL_PASSWORD` | Пароль этого пользователя |
| `volumes` | Постоянное хранилище данных MySQL |
| `restart: unless-stopped` | Контейнер будет перезапускаться, если его явно не остановили |

### Почему здесь используется `mysql_data`, а не `./mysql:/var/lib/mysql`

В исходном варианте использовалась папка `./mysql` и команда:

```bash
chmod 777 ./mysql
```

Для учебного занятия это может создать лишние сложности с правами доступа. Поэтому в обновлённом варианте используется именованный Docker volume `mysql_data`. Это проще для начинающих: Docker сам управляет папкой, где физически лежат данные MySQL.

---

## 4. Запуск контейнера

В терминале перейдите в папку, где лежит `docker-compose.yml`, и выполните:

```bash
docker compose up -d
```

Что делает команда:

- `docker compose` — запускает сервисы из файла `docker-compose.yml`;
- `up` — поднять сервисы;
- `-d` — запустить в фоновом режиме, чтобы терминал остался свободным.

Проверим, что контейнер работает:

```bash
docker ps
```

В списке должен быть контейнер `mysql_container`.

---

## 5. Подключение к MySQL

Выполните команду:

```bash
docker exec -it mysql_container mysql -u root -p
```

После этого MySQL попросит пароль.

Введите:

```text
root
```

Пароль при вводе может не отображаться. Это нормально.

Если всё получилось, вы увидите приглашение MySQL:

```text
mysql>
```

Теперь команды нужно писать уже не в обычный терминал, а внутри MySQL.

---

## 6. Проверка подключения к порту MySQL

Эта команда выполняется в обычном терминале, не внутри MySQL:

```bash
nc -zv 127.0.0.1 3306
```

Если соединение успешно, значит MySQL доступен на локальном компьютере через порт `3306`.

# Часть 1. Создание базы данных

## 7. Посмотреть список баз данных

Команда:

```sql
SHOW DATABASES;
```

Эта команда показывает все базы данных, которые сейчас есть в MySQL.

Пример результата:

```text
+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| sys                |
| testdb             |
+--------------------+
```

Служебные базы `information_schema`, `mysql`, `performance_schema`, `sys` создаются самим MySQL. Их пока не трогаем.

---

## 8. Создать новую базу данных

Создадим базу для занятия:

```sql
CREATE DATABASE my_database;
```

Если база создалась успешно, MySQL ответит примерно так:

```text
Query OK, 1 row affected
```

Это означает, что команда выполнена без ошибки.

### Более безопасный вариант

Если вы запускаете команду повторно, база уже может существовать. Тогда лучше использовать:

```sql
CREATE DATABASE IF NOT EXISTS my_database;
```

Фраза `IF NOT EXISTS` означает: «создай базу, если её ещё нет».

---

## 9. Выбрать активную базу данных

Создать базу недостаточно. Нужно ещё сказать MySQL, что дальше мы хотим работать именно с ней.

```sql
USE my_database;
```

Ожидаемый ответ:

```text
Database changed
```

Теперь все следующие команды будут выполняться внутри базы `my_database`.

## 10. Посмотреть таблицы в текущей базе

Если база пустая, результат будет таким:


Это не ошибка. Это значит, что таблиц пока нет.

# Часть 2. Создание таблицы `users`

## 11. Бизнес-сценарий

Представим, что у нас есть интернет-магазин. Нам нужно хранить информацию о пользователях:

- уникальный номер пользователя;
- имя;
- email;
- возраст;
- страна;
- баланс счёта.

Для этого создадим таблицу `users`.

---

## 12. Создание таблицы

```sql
CREATE TABLE users (
    id INT NOT NULL AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    age INT NOT NULL,
    country VARCHAR(50) NOT NULL,
    balance DECIMAL(10, 2) NOT NULL,
    PRIMARY KEY (id)
);
```

### Разбор структуры таблицы

| Поле | Тип | Что хранит |
|---|---|---|
| `id` | `INT` | Уникальный номер пользователя |
| `name` | `VARCHAR(50)` | Имя пользователя, максимум 50 символов |
| `email` | `VARCHAR(100)` | Email пользователя |
| `age` | `INT` | Возраст |
| `country` | `VARCHAR(50)` | Страна |
| `balance` | `DECIMAL(10, 2)` | Баланс с двумя знаками после запятой |

### Важные элементы команды

| Элемент | Объяснение |
|---|---|
| `CREATE TABLE users` | Создать таблицу с именем `users` |
| `NOT NULL` | Поле обязательно должно быть заполнено |
| `AUTO_INCREMENT` | MySQL сам увеличивает номер `id` для новой строки |
| `PRIMARY KEY (id)` | `id` становится главным уникальным идентификатором строки |
| `DECIMAL(10, 2)` | Число до 10 цифр, из них 2 после запятой |

### Почему для денег используем `DECIMAL`, а не `FLOAT`

В исходном файле поле `balance` было задано как `FLOAT`. Для учебного примера это может работать, но для денежных значений лучше сразу использовать `DECIMAL(10, 2)`.

Причина: `DECIMAL` хранит точные числовые значения, а `FLOAT` относится к приблизительным типам. Для денег, цен и балансов точность важнее.

# Часть 6. Сортировка через `ORDER BY`

## 26. Отсортировать пользователей по балансу по возрастанию

```sql
SELECT *
FROM users
```

По умолчанию `ORDER BY` сортирует по возрастанию: от меньшего значения к большему.

---

## 27. Отсортировать пользователей по балансу по убыванию

```sql

FROM users

```

`DESC` означает убывание: от большего значения к меньшему.

Противоположный вариант — `ASC`, сортировка по возрастанию:

```sql
SELECT *
FROM users
```


Такой запрос сначала сортирует пользователей по стране, а внутри каждой страны — по балансу от большего к меньшему.

# Часть 7. Агрегатные функции

Агрегатные функции считают один итоговый показатель по набору строк.

| Функция | Что делает |
|---|---|
| `COUNT()` | Считает количество строк |
| `AVG()` | Считает среднее значение |
| `SUM()` | Считает сумму |
| `MAX()` | Находит максимум |
| `MIN()` | Находит минимум |

---

# Часть 8. Изменение данных через `UPDATE`

## 36. Главное правило безопасности

Перед изменением данных всегда сначала делаем проверочный `SELECT`.

Шаблон безопасной работы:

```sql
SELECT *
FROM users
WHERE id = 2;
```

Если результат правильный, только потом выполняем `UPDATE`:

```sql
UPDATE users
SET balance = 110000
WHERE id = 2;
```

После этого снова проверяем:

```sql
SELECT *
FROM users
WHERE id = 2;
```

---

## 37. Обновить баланс одного пользователя

```sql
UPDATE users
SET balance = 110000
WHERE id = 2;
```

Разбор:

| Часть команды | Что означает |
|---|---|
| `UPDATE users` | Обновляем таблицу `users` |
| `SET balance = 110000` | Устанавливаем новое значение баланса |
| `WHERE id = 2` | Меняем только строку, где `id = 2` |

---

## 38. Опасный пример: `UPDATE` без `WHERE`

Ниже пример, который нельзя выполнять без понимания последствий:

```sql
UPDATE users
SET name = 'Ivan';
```

Эта команда изменит имя у всех пользователей в таблице.

Почему это опасно:

- нет условия `WHERE`;
- MySQL не знает, какую конкретную строку нужно изменить;
- поэтому команда применится ко всем строкам.

Правильный вариант для изменения одного пользователя:

```sql
UPDATE users
SET name = 'Gleb'
WHERE id = 2;
```

Запомните правило:

```text
Нет WHERE в UPDATE — почти всегда риск испортить всю таблицу.
```

## 39. Восстановить имена после ошибочного обновления

Если на занятии вы специально показали опасный пример и все имена стали `Ivan`, можно восстановить данные так:

```sql
UPDATE users SET name = 'Gleb' WHERE id = 2;
UPDATE users SET name = 'Sergey' WHERE id = 3;
UPDATE users SET name = 'Andrew' WHERE id = 4;
UPDATE users SET name = 'Bob' WHERE id = 5;
UPDATE users SET name = 'Tom' WHERE id = 6;
```

После восстановления проверяем таблицу:

```sql
SELECT *
FROM users;
```

# Часть 9. Удаление данных через `DELETE`

## 41. Безопасное удаление строки

Перед удалением тоже сначала делаем проверочный `SELECT`.

```sql
SELECT *
FROM users
WHERE id = 5;
```

Если это действительно нужная строка, выполняем удаление:

```sql
DELETE FROM users
WHERE id = 5;
```

После удаления проверяем таблицу:

```sql
SELECT *
FROM users;
```

---

## 42. Опасный пример: `DELETE` без `WHERE`

Нельзя бездумно выполнять:

```sql
DELETE FROM users;
```

Эта команда удалит все строки из таблицы `users`.

Правило:

```text
Нет WHERE в DELETE — можно удалить всю таблицу данных.
```

# Часть 12. Типичные ошибки новичков

| Ошибка | Почему возникает | Как исправить |
|---|---|---|
| Забыли `;` | MySQL ждёт продолжения команды | Добавить `;` и нажать Enter |
| Не выбрали базу через `USE` | MySQL не знает, где создавать таблицу | Выполнить `USE my_database;` |
| Ошибка в имени таблицы | Написали `user` вместо `users` | Проверить через `SHOW TABLES;` |
| Ошибка в имени столбца | Написали `balanse` вместо `balance` | Проверить через `DESCRIBE users;` |
| `UPDATE` изменил все строки | Не было `WHERE` | Сначала делать `SELECT`, потом `UPDATE` |
| `DELETE` удалил лишнее | Не было точного условия | Сначала делать `SELECT`, потом `DELETE` |
| Путают строки и столбцы | Нет визуального понимания таблицы | Сравнить с Excel: строки — записи, столбцы — признаки |
