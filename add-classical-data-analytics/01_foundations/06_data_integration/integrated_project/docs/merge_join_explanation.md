# Раздатка: merge / join для начинающих

## Тема

**Объединение таблиц в pandas: `merge`, ключи и join-операции**

Эта раздатка предназначена для слушателей начального уровня.  
Цель — простыми словами понять, как аналитик объединяет несколько таблиц в одну.

---

# 1. Зачем нужно объединять таблицы

В реальной аналитике данные редко лежат в одной готовой таблице.

Например, у компании есть:

```text
sales.csv        — продажи
products.xlsx    — справочник товаров
regions.json     — справочник регионов
clients.csv      — справочник клиентов
```

В таблице продаж может быть только код товара:

| sale_id | product_id | quantity |
|---:|---:|---:|
| 1 | 101 | 2 |
| 2 | 102 | 1 |
| 3 | 999 | 5 |

А в справочнике товаров — расшифровка:

| product_id | product_name | category |
|---:|---|---|
| 101 | Ноутбук | электроника |
| 102 | Мышь | аксессуары |

Чтобы получить нормальную аналитическую таблицу, нужно добавить к продажам название товара и категорию.

Итог должен стать таким:

| sale_id | product_id | quantity | product_name | category |
|---:|---:|---:|---|---|
| 1 | 101 | 2 | Ноутбук | электроника |
| 2 | 102 | 1 | Мышь | аксессуары |
| 3 | 999 | 5 | NaN | NaN |

Именно для этого нужен `merge`.

---

# 2. Бытовая аналогия

Представьте гардероб в театре.

У посетителя есть номерок:

```text
№ 101
```

У гардеробщика есть список:

| Номерок | Куртка |
|---:|---|
| 101 | черная куртка |
| 102 | синее пальто |

Номерок — это **ключ**.

Чтобы вернуть куртку, гардеробщик ищет номерок посетителя в своем списке.

Если номерок найден — посетитель получает куртку.  
Если номерок не найден — куртка не найдена, возникает проблема.

В таблицах происходит то же самое:

```text
product_id в продажах
ищется в
product_id в справочнике товаров
```

Если совпадение найдено, pandas добавляет данные из справочника.  
Если совпадение не найдено, появляются пустые значения `NaN`.

---

# 3. Что такое ключ

**Ключ** — это столбец, по которому таблицы соединяются.

Примеры ключей:

| Что соединяем | Ключ |
|---|---|
| Продажи + товары | `product_id` |
| Продажи + клиенты | `client_id` |
| Продажи + регионы | `region_id` |
| Продажи + план | `region_id + channel + month` |

Ключ должен отвечать на вопрос:

> по какому признаку pandas поймет, какие строки из разных таблиц относятся друг к другу?

---

# 4. Что такое merge

`merge()` — это команда pandas для объединения таблиц по ключу.

Пример:

```python
sales_products = sales.merge(
    products,
    on="product_id",
    how="left"
)
```

Читается так:

> возьми таблицу `sales`, найди в ней `product_id`, найди такой же `product_id` в таблице `products` и добавь к продажам информацию о товаре.

---

# 5. Базовый синтаксис merge

```python
result = left_table.merge(
    right_table,
    on="key_column",
    how="left"
)
```

Где:

| Параметр | Что означает |
|---|---|
| `left_table` | левая, основная таблица |
| `right_table` | правая таблица, чаще справочник |
| `on` | столбец-ключ для объединения |
| `how` | тип объединения: `left`, `inner`, `outer` |

---

# 6. Left join

## 6.1. Простое объяснение

**Left join** сохраняет все строки из левой таблицы.

Если в правой таблице найдено совпадение — данные добавятся.  
Если совпадение не найдено — появятся `NaN`.

## 6.2. Бытовая аналогия

Есть список всех продаж.  
К каждой продаже мы хотим добавить товар.

Продажи — главная таблица.  
Даже если товар не найден в справочнике, сама продажа не должна исчезнуть.

## 6.3. Пример

Левая таблица `sales`:

| sale_id | product_id | quantity |
|---:|---:|---:|
| 1 | 101 | 2 |
| 2 | 102 | 1 |
| 3 | 999 | 5 |

Правая таблица `products`:

| product_id | product_name |
|---:|---|
| 101 | Ноутбук |
| 102 | Мышь |

Код:

```python
sales_products = sales.merge(
    products,
    on="product_id",
    how="left"
)
```

Результат:

| sale_id | product_id | quantity | product_name |
|---:|---:|---:|---|
| 1 | 101 | 2 | Ноутбук |
| 2 | 102 | 1 | Мышь |
| 3 | 999 | 5 | NaN |

## 6.4. Когда использовать left join

Используйте `left join`, когда:

- левая таблица — главная;
- нельзя терять строки из левой таблицы;
- нужно увидеть, какие значения не нашли совпадения.

Для учебного кейса:

```python
sales.merge(products, on="product_id", how="left")
```

обычно безопаснее, чем `inner`.

---

# 7. Inner join

## 7.1. Простое объяснение

**Inner join** оставляет только те строки, где ключ найден в обеих таблицах.

Если продажа не нашла товар в справочнике, такая продажа исчезнет из результата.

## 7.2. Бытовая аналогия

На мероприятие пускают только тех людей, кто есть одновременно:

- в списке зарегистрированных;
- в списке оплативших.

Если человек есть только в одном списке, его не включают в итоговый список.

## 7.3. Пример

```python
sales_products_inner = sales.merge(
    products,
    on="product_id",
    how="inner"
)
```

Результат:

| sale_id | product_id | quantity | product_name |
|---:|---:|---:|---|
| 1 | 101 | 2 | Ноутбук |
| 2 | 102 | 1 | Мышь |

Продажа с `product_id = 999` исчезла, потому что такого товара нет в справочнике.

## 7.4. Когда использовать inner join

Используйте `inner join`, когда:

- нужны только полностью сопоставленные строки;
- потеря строк допустима;
- вы заранее понимаете, почему часть данных может исчезнуть.

Для начинающих аналитиков важно помнить:

> `inner join` может незаметно удалить строки и исказить итоговую выручку.

---

# 8. Outer join

## 8.1. Простое объяснение

**Outer join** сохраняет все ключи из обеих таблиц.

Он показывает:

- что есть только в левой таблице;
- что есть только в правой таблице;
- что совпало в обеих.

## 8.2. Бытовая аналогия

Есть два списка:

- список людей, которые зарегистрировались;
- список людей, которые оплатили.

`outer join` делает полный список всех людей:

- кто и зарегистрировался, и оплатил;
- кто только зарегистрировался;
- кто только оплатил.

## 8.3. Пример

```python
sales_products_outer = sales.merge(
    products,
    on="product_id",
    how="outer",
    indicator=True
)
```

`outer join` часто используют для диагностики: посмотреть, какие ключи не совпадают.

## 8.4. Когда использовать outer join

Используйте `outer join`, когда нужно:

- найти несовпадающие ключи;
- проверить справочники;
- понять, что есть только слева и только справа;
- провести диагностику качества данных.

---

# 9. Сравнение left, inner и outer

| Тип join | Что сохраняет | Что происходит с несовпадениями | Когда использовать |
|---|---|---|---|
| `left` | Все строки из левой таблицы | Справа появляются `NaN` | Основной вариант для добавления справочников к продажам |
| `inner` | Только совпавшие строки | Несовпавшие строки удаляются | Когда нужны только полные совпадения |
| `outer` | Все строки из обеих таблиц | `NaN` появляются с обеих сторон | Для диагностики несовпадающих ключей |

---

# 10. Почему появляются NaN после merge

`NaN` после `merge` обычно означает:

> pandas не нашел подходящую строку в другой таблице.

Пример:

В продажах есть:

| sale_id | product_id |
|---:|---:|
| 3 | 999 |

А в товарах есть только:

| product_id | product_name |
|---:|---|
| 101 | Ноутбук |
| 102 | Мышь |

После `left merge`:

| sale_id | product_id | product_name |
|---:|---:|---|
| 3 | 999 | NaN |

Потому что `product_id = 999` не найден в справочнике товаров.

---

# 11. Основные причины NaN после merge

| Причина | Пример | Что проверить |
|---|---|---|
| Ключа нет в справочнике | `product_id = 999` отсутствует в `products` | Разницу множеств ключей |
| Разный тип ключа | в одной таблице `101`, в другой `"101"` | `df.dtypes` |
| Лишние пробелы | `"A001"` и `" A001 "` | `.str.strip()` |
| Разный регистр | `"Online"` и `"online"` | `.str.lower()` |
| Ошибка в данных | неправильный код товара | исходный файл |
| Неполный справочник | справочник не содержит все значения | обновить справочник |

---

# 12. Как заранее проверить ключи

Перед объединением полезно проверить, какие ключи есть в левой таблице, но отсутствуют в правой.

```python
missing_product_ids = (
    set(sales["product_id"].dropna().unique()) -
    set(products["product_id"].dropna().unique())
)

missing_product_ids
```

Если результат не пустой, значит часть продаж не найдет товар.

# 13. Как проверить, что merge прошел корректно

## 13.1. Проверка 1: количество строк до и после

```python
rows_before = sales.shape[0]

sales_products = sales.merge(
    products,
    on="product_id",
    how="left"
)

rows_after = sales_products.shape[0]

print("До merge:", rows_before)
print("После merge:", rows_after)
```

Для `left join` со справочником обычно ожидаем:

```text
rows_before == rows_after
```

Если строк стало больше, возможно, в справочнике есть дубликаты ключей.

---

## 13.2. Проверка 2: indicator=True

```python
sales_products = sales.merge(
    products,
    on="product_id",
    how="left",
    indicator=True
)

sales_products["_merge"].value_counts()
```

Столбец `_merge` покажет:

| Значение | Что означает |
|---|---|
| `both` | ключ найден в обеих таблицах |
| `left_only` | строка есть только в левой таблице |
| `right_only` | строка есть только в правой таблице |

Для `left join` важны:

```text
both
left_only
```

Если есть `left_only`, значит часть строк не нашла соответствие в справочнике.

---

## 13.3. Проверка 3: посмотреть строки left_only

```python
sales_products[
    sales_products["_merge"] == "left_only"
]
```

Для продаж и товаров лучше вывести только важные столбцы:

```python
sales_products[
    sales_products["_merge"] == "left_only"
][
    ["sale_id", "product_id", "product_name"]
]
```

---

## 13.4. Проверка 4: validate

`validate` помогает проверить ожидаемый тип связи.

Для продаж и справочника товаров обычно связь такая:

```text
many_to_one
```

Это значит:

- в продажах один товар может встречаться много раз;
- в справочнике товаров каждый `product_id` должен быть один раз.

```python
sales_products = sales.merge(
    products,
    on="product_id",
    how="left",
    validate="many_to_one"
)
```

Если в справочнике есть дубликаты `product_id`, pandas выдаст ошибку.  
Это хорошо: ошибка защищает нас от неправильного результата.

---

# 14. Полный безопасный шаблон merge

Используйте такой шаблон в учебных и рабочих задачах:

```python
rows_before = sales.shape[0]

sales_products = sales.merge(
    products,
    on="product_id",
    how="left",
    indicator=True,
    validate="many_to_one"
)

rows_after = sales_products.shape[0]

print("Строк до merge:", rows_before)
print("Строк после merge:", rows_after)
print("Изменение строк:", rows_after - rows_before)

print(sales_products["_merge"].value_counts())

sales_products[
    sales_products["_merge"] == "left_only"
].head()
```

После проверки можно удалить диагностический столбец:

```python
sales_products = sales_products.drop(columns=["_merge"])
```

---

# 15. Что делать, если после merge стало больше строк

Если после `left merge` строк стало больше, частая причина — дубликаты ключа в правой таблице.

Пример:

`sales`:

| sale_id | product_id |
|---:|---:|
| 1 | 101 |

`products`:

| product_id | product_name |
|---:|---|
| 101 | Ноутбук |
| 101 | Ноутбук новая карточка |

После merge получится две строки вместо одной.

Проверка:

```python
products.duplicated(subset=["product_id"]).sum()
```

Посмотреть дубликаты:

```python
products[
    products.duplicated(subset=["product_id"], keep=False)
]
```

Удалить дубликаты, если это допустимо:

```python
products = products.drop_duplicates(subset=["product_id"], keep="first")
```

Важно:

> удалять дубликаты можно только после понимания причины. Иногда разные строки с одним ключом означают разные версии, даты или статусы.

---

# 16. Что делать, если после merge много NaN

Проверить несовпадающие ключи:

```python
missing_product_ids = (
    set(sales["product_id"].dropna().unique()) -
    set(products["product_id"].dropna().unique())
)

missing_product_ids
```

Проверить типы ключей:

```python
sales["product_id"].dtype
products["product_id"].dtype
```

Если типы разные, привести к одному типу:

```python
sales["product_id"] = sales["product_id"].astype("string")
products["product_id"] = products["product_id"].astype("string")
```

Для текстовых ключей убрать пробелы:

```python
sales["product_id"] = sales["product_id"].astype("string").str.strip()
products["product_id"] = products["product_id"].astype("string").str.strip()
```

# 17. Объединение по нескольким ключам

Иногда одного ключа недостаточно.

Например, план продаж может быть задан по комбинации:

```text
region_id + channel + month
```

Тогда объединяем по списку ключей:

```python
sales_with_plan = sales.merge(
    plans,
    on=["region_id", "channel", "month"],
    how="left",
    indicator=True,
    validate="many_to_one"
)
```

Это означает:

> строка считается совпавшей только тогда, когда совпали все три значения: регион, канал и месяц.

---

# 18. Типовые ошибки начинающих

| Ошибка | Что происходит | Как исправить |
|---|---|---|
| Использовали `inner` вместо `left` | Потеряли часть строк | Для фактов продаж чаще использовать `left` |
| Не проверили строки до/после | Не заметили размножение строк | Сравнивать `shape[0]` |
| Не проверили `_merge` | Не увидели несовпавшие ключи | Использовать `indicator=True` |
| Не проверили дубликаты в справочнике | Строк стало больше | Использовать `duplicated()` и `validate` |
| Не привели типы ключей | Много `NaN` после merge | Проверить `dtypes` |
| Не очистили текстовые ключи | Ключи не совпали из-за пробелов/регистра | `.str.strip()`, `.str.lower()` |
| Удалили `NaN` без анализа | Потеряли важные факты | Сначала выяснить причину `NaN` |

# 19. Мини-шпаргалка

## Left join

```python
result = left.merge(right, on="key", how="left")
```

Сохраняет все строки слева.

## Inner join

```python
result = left.merge(right, on="key", how="inner")
```

Оставляет только совпавшие строки.

## Outer join

```python
result = left.merge(right, on="key", how="outer")
```

Сохраняет все строки из обеих таблиц.

## Диагностика

```python
result = left.merge(
    right,
    on="key",
    how="left",
    indicator=True,
    validate="many_to_one"
)

result["_merge"].value_counts()
```

## Проверка строк

```python
left.shape[0]
result.shape[0]
```

## Проверка дубликатов ключа

```python
right.duplicated(subset=["key"]).sum()
```

# 20. Как объяснить merge за 1 минуту

> `merge` — это способ соединить две таблицы по общему столбцу-ключу.  
> Ключ — это как номерок в гардеробе: по нему мы ищем нужную запись во второй таблице.  
> `left join` сохраняет все строки главной таблицы и добавляет данные из справочника.  
> `inner join` оставляет только совпавшие строки.  
> `outer join` показывает все строки из обеих таблиц и помогает искать несовпадения.  
> `NaN` после объединения означает, что pandas не нашел совпадение по ключу.  
> После каждого объединения нужно проверять количество строк, `_merge`, дубликаты ключей и пропуски.

# 22. Практическое задание

Есть две таблицы.

```python
sales = pd.DataFrame({
    "sale_id": [1, 2, 3],
    "product_id": [101, 102, 999],
    "quantity": [2, 1, 5]
})

products = pd.DataFrame({
    "product_id": [101, 102],
    "product_name": ["Ноутбук", "Мышь"],
    "category": ["электроника", "аксессуары"]
})
```

Выполните:

1. `left join`;
2. `inner join`;
3. `outer join`;
4. сравните количество строк;
5. найдите строки `left_only`;
6. объясните, почему появился `NaN`.

Шаблон:

```python
result = sales.merge(
    products,
    on="product_id",
    how="left",
    indicator=True,
    validate="many_to_one"
)

result
result["_merge"].value_counts()
```

# 23. Итог

Главное правило:

> объединение таблиц — один из самых рискованных этапов анализа данных.

После каждого `merge` нужно проверять:

```text
количество строк до и после
↓
совпадения через _merge
↓
дубликаты ключей
↓
NaN в добавленных столбцах
↓
типы и чистоту ключей
```

Если этого не делать, можно получить красивый отчет с неправильной выручкой, неправильными регионами или потерянными продажами.
