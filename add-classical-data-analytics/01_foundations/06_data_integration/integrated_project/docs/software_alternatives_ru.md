# Стек ПО и альтернативы, доступные в РФ

## 1. Назначение документа

Документ подготовлен для учебного комплекта по теме:

**«Загрузка и интеграция данных из различных форматов. Инструменты для сбора данных. Основы Python для обработки данных»**

Цель документа — помочь лектору и организаторам выбрать рабочий стек для занятия в условиях, когда:

- часть зарубежных сервисов может быть недоступна;
- Wi‑Fi в аудитории может быть нестабильным;
- установка ПО может ограничиваться политиками организации;
- нужны понятные российские или локально устанавливаемые альтернативы;
- слушатели находятся на начальном уровне.

Документ не является юридическим заключением по лицензированию и импортозамещению. Перед промышленным использованием инструменты нужно проверять с ИТ, ИБ, закупками и юридической службой организации.

# 4. Инструменты для ноутбуков и Python-разработки

## 4.1. JupyterLab

### Назначение

JupyterLab — интерактивная среда для работы с ноутбуками, кодом и данными. Подходит для учебных занятий, где нужно совмещать:

- текстовые пояснения;
- Python-код;
- вывод таблиц;
- графики;
- пошаговые задания.

Официально Project Jupyter описывает JupyterLab как современную веб-среду для ноутбуков, кода и данных.

### Плюсы

- Понятен начинающим.
- Хорошо подходит для пошагового обучения.
- Работает локально без интернета после установки.
- Удобно сочетает Markdown, код и результаты.
- Подходит для демонстрации `pandas`, графиков, загрузки CSV/Excel/JSON/HTML.

### Ограничения

- Начинающие могут запускать ячейки не по порядку.
- Состояние переменных зависит от порядка выполнения.
- Для больших проектов менее удобен, чем IDE.
- Нужно отдельно объяснять Kernel, рабочую папку и перезапуск ядра.

### Когда использовать

Использовать как основной инструмент для слушателей на начальном уровне.

Рекомендуемые ноутбуки:

```text
00_setup_and_check.ipynb
01_data_loading_formats.ipynb
02_dataframe_types_and_quality.ipynb
03_data_integration.ipynb
04_basic_analysis.ipynb
05_basic_visualization.ipynb
06_python_to_r_bridge.ipynb
```

### Когда не использовать

- Когда нужен большой программный проект.
- Когда важнее структура `.py`-модулей, тесты и Git workflow.
- Когда организация запрещает локальные notebook-среды.

---

## 4.2. VS Code

### Назначение

VS Code — универсальная IDE для проекта. В контексте курса подходит для:

- открытия всей папки проекта;
- запуска `.ipynb`;
- запуска `.py`;
- выбора Python-интерпретатора;
- работы с терминалом;
- просмотра переменных;
- запуска R-скриптов через расширение R.

VS Code поддерживает Jupyter Notebooks через Jupyter extension, включая запуск ячеек, просмотр переменных и Data Viewer.

### Плюсы

- Один интерфейс для `.ipynb`, `.py`, `.R`, Markdown и терминала.
- Удобно объяснять структуру проекта.
- Есть интеграция с Python-окружениями.
- Есть Jupyter-поддержка.
- Есть терминал внутри IDE.
- Удобен для перехода от ноутбуков к инженерному стилю работы.

### Ограничения

- Требует установки расширений.
- Начинающим сложнее, чем чистый JupyterLab.
- Возможны проблемы с выбором интерпретатора и Kernel.
- В организациях могут быть ограничения на установку расширений.

### Когда использовать

Использовать, если нужно показать:

- структуру проекта;
- работу с `.py`;
- запуск `environment_check.py`;
- терминал;
- R-скрипты;
- связку Python + R.

### Когда не использовать

Если группа совсем начального уровня и занятие должно быть максимально простым, можно начать с JupyterLab, а VS Code оставить как дополнительный вариант.

# 5. Облачные среды и российские альтернативы Colab

## 5.1. Yandex DataSphere

### Назначение

Yandex DataSphere — облачный сервис для анализа данных и машинного обучения. Он подходит для случаев, когда:

- у слушателей слабые ноутбуки;
- нужны управляемые вычислительные ресурсы;
- нужна среда Jupyter Notebook в облаке;
- нужно дать одинаковую среду группе.

Yandex Cloud описывает DataSphere как сервис полного цикла для разработки, анализа данных и создания ML-моделей, с привычными инструментами Jupyter Notebook и масштабируемыми ресурсами облака.

### Плюсы

- Российская облачная платформа.
- Можно работать без установки тяжелого локального окружения.
- Подходит для ML и анализа данных.
- Есть управляемые вычислительные ресурсы.
- Удобно для единообразной среды обучения.

### Ограничения

- Требуется аккаунт и доступ к облаку.
- Нужен интернет.
- Возможны расходы по тарифам.
- Требуется настройка прав доступа и платежного аккаунта.
- Для корпоративного использования нужно согласование с ИБ и закупками.

### Когда использовать

Использовать, если:

- занятие проходит онлайн;
- нужна единая облачная среда;
- локальные компьютеры слабые;
- нужна демонстрация облачного DS/ML workflow;
- есть подтвержденный доступ к Yandex Cloud.

### Когда не использовать

- При занятии без Wi‑Fi.
- Если нет согласованного облачного аккаунта.
- Если данные нельзя выносить во внешнюю облачную среду.

## 5.2. Cloud.ru ML Space

### Назначение

Cloud.ru ML Space — российская платформа для ML-разработки полного цикла и совместной работы Data Science-команд. В учебном контексте ее можно рассматривать как облачную альтернативу для задач машинного обучения, обучения моделей, совместной разработки и работы с вычислительными ресурсами.

В документации и описаниях Cloud.ru ML Space указывается как ML-платформа для полного цикла, а Cloud.ru Evolution предоставляет доступ к IaaS/PaaS, GPU, выделенным серверам и AI-инструментам.

### Плюсы

- Российская облачная ML-платформа.
- Подходит для ML-команд и командной разработки.
- Может использовать высокопроизводительную инфраструктуру.
- Подходит для сценариев с GPU и промышленной ML-разработкой.
- Есть связь с российским реестром ПО для ML Space.

### Ограничения

- Для простого занятия по `pandas` может быть избыточна.
- Требуется интернет и доступ к облаку.
- Нужны учетные записи, права и лимиты.
- Требуется согласование по стоимости и безопасности.
- Настройка сложнее, чем локальный JupyterLab.

### Когда использовать

Использовать, если:

- занятие связано с ML-инфраструктурой;
- нужна демонстрация промышленного DS/ML-процесса;
- нужно показать российскую cloud/ML-платформу;
- есть корпоративный доступ.

### Когда не использовать

- Для базового занятия по CSV/Excel/JSON/HTML.
- В офлайн-аудитории.
- Если цель — простая локальная обработка данных.

# 6. Офисные пакеты для таблиц и проверки файлов

## 6.1. LibreOffice

### Назначение

LibreOffice — свободный офисный пакет. В курсе он нужен для:

- просмотра CSV;
- просмотра Excel-файлов;
- быстрой ручной проверки таблиц;
- открытия `.xlsx`, если Microsoft Office недоступен.

LibreOffice официально позиционируется как бесплатный и открытый офисный пакет.

### Плюсы

- Бесплатный и open source.
- Работает локально.
- Подходит для просмотра и редактирования таблиц.
- Удобен для офлайн-занятия.
- Может открывать распространенные офисные форматы.

### Ограничения

- Совместимость со сложными Excel-файлами может быть неидеальной.
- Формулы, макросы, форматирование и сводные таблицы могут отличаться от Microsoft Excel.
- Интерфейс может быть непривычен пользователям Excel.

### Когда использовать

Использовать как базовую бесплатную альтернативу Excel для учебных данных.

### Когда не использовать

Если в организации утвержден конкретный отечественный офисный пакет или нужны корпоративные функции совместной работы.

---

## 6.2. Р7-Офис

### Назначение

Р7-Офис — российский офисный пакет для работы с документами, таблицами и презентациями. В учебном комплекте его можно использовать вместо Microsoft Office или LibreOffice для просмотра CSV/XLSX и проверки результатов.

Официальные и партнерские описания позиционируют Р7-Офис как российский офисный пакет, представленный в десктопной, серверной и облачной версиях.

### Плюсы

- Российский офисный продукт.
- Подходит для организаций, где требуется отечественное ПО.
- Есть варианты для бизнеса и образования.
- Может использоваться для просмотра и редактирования офисных файлов.
- Подходит для проверки `products.xlsx`, `sales_prepared.xlsx`, аналитических отчетов.

### Ограничения

- Может требовать лицензии.
- Возможности зависят от редакции.
- Необходимо заранее проверить совместимость с учебными файлами.
- Для аудитории нужно заранее установить и активировать.

### Когда использовать

Использовать, если:

- организация использует Р7-Офис как стандарт;
- требуется российский офисный пакет;
- нужно просматривать Excel-результаты без Microsoft Office.

### Когда не использовать

Если достаточно бесплатного LibreOffice и нет требований по конкретному корпоративному офисному пакету.

---

## 6.3. МойОфис

### Назначение

МойОфис — российский офисный пакет для работы с текстами, таблицами, презентациями и PDF. В учебном комплекте полезен для открытия и проверки офисных файлов.

Официальное описание МойОфис указывает работу с документами разных форматов, включая `.docx`, `.xlsx`, `.pptx`, `.odt`, `.ods`, `.odp`, а также PDF.

### Плюсы

- Российская офисная экосистема.
- Подходит для организаций с политикой импортозамещения.
- Можно использовать для просмотра таблиц и отчетов.
- Есть варианты для разных сценариев использования.
- Может работать без интернета в локальных сценариях, если установлен заранее.

### Ограничения

- Функциональность зависит от редакции.
- Может требовать лицензии.
- Нужно заранее проверить совместимость с конкретными `.xlsx`.
- Не заменяет аналитические инструменты Python/R.

### Когда использовать

Использовать, если:

- МойОфис уже принят в организации;
- требуется российский офисный пакет;
- нужно открыть Excel-отчеты и проверить CSV/XLSX.

### Когда не использовать

Если цель — аналитическая обработка данных. Для обработки использовать Python/R, а офисный пакет — только для просмотра и ручной проверки.

# 7. Локальные базы данных и SQL

## 7.1. SQLite

### Назначение

SQLite — легковесная встроенная SQL-база данных. В курсе подходит для:

- объяснения SQL без сервера;
- хранения небольших таблиц;
- демонстрации `SELECT`, `WHERE`, `GROUP BY`, `JOIN`;
- офлайн-сценария.

Официальный сайт SQLite описывает SQLite как небольшую, быструю, самодостаточную и надежную SQL database engine.

### Плюсы

- Не нужен сервер.
- Обычно доступна в Python через стандартный модуль `sqlite3`.
- Хорошо подходит для базового SQL.
- Удобна для офлайн-занятий.
- Один файл базы легко передавать.

### Ограничения

- Не предназначена для тяжелой многопользовательской аналитики.
- Не лучший выбор для больших аналитических выгрузок.
- Меньше возможностей аналитического SQL по сравнению с DuckDB.
- Для работы с Parquet/CSV напрямую удобнее DuckDB.

### Когда использовать

Использовать для начального SQL:

```text
таблица → SQL-запрос → результат
```

### Когда не использовать

Если нужно активно анализировать CSV/Parquet, выполнять тяжелые аналитические запросы или строить витрины поверх файлов.

---

## 7.2. DuckDB

### Назначение

DuckDB — встроенная аналитическая OLAP SQL-база. В учебном комплекте подходит для:

- SQL-запросов по аналитическим таблицам;
- чтения CSV/Parquet;
- передачи данных между Python и R;
- локального аналитического workflow без отдельного сервера.

Официальный сайт DuckDB описывает его как open-source in-process SQL OLAP database management system.

### Плюсы

- Не нужен отдельный сервер.
- Хорошо подходит для аналитических запросов.
- Удобно работает из Python и R.
- Подходит для Parquet и аналитических витрин.
- Один `.duckdb`-файл можно передавать между инструментами.
- Хорошо подходит для ноутбуков и локального анализа.

### Ограничения

- Это не замена промышленной клиент-серверной СУБД для многопользовательских транзакций.
- Новичкам нужно объяснить отличие DuckDB от SQLite.
- Для некоторых расширенных возможностей нужны дополнительные настройки.
- Не всегда нужен для совсем базового занятия.

### Когда использовать

Использовать в курсе:

- для `06_python_to_r_bridge.ipynb`;
- для аналитического SQL;
- для демонстрации локальной аналитической базы;
- для формата обмена Python → R.

### Когда не использовать

Если задача — только показать простые SQL-команды. Тогда SQLite проще.

---

## 7.3. DBeaver

### Назначение

DBeaver — универсальный SQL-клиент и инструмент управления базами данных. В курсе полезен для:

- визуального подключения к SQLite/DuckDB/PostgreSQL/MySQL;
- просмотра таблиц;
- выполнения SQL-запросов;
- объяснения структуры базы данных.

DBeaver Community официально описывается как бесплатный open-source инструмент управления базами данных, поддерживающий MySQL, MariaDB, PostgreSQL, SQLite и другие базы.

### Плюсы

- Удобный визуальный интерфейс.
- Поддерживает множество баз.
- Подходит для SQL-практики.
- Есть бесплатная Community-версия.
- Удобно показывать таблицы и результаты запросов.

### Ограничения

- Для начинающих может быть перегружен интерфейсом.
- Нужны драйверы для некоторых СУБД.
- Для простых ноутбуков можно обойтись pandas/DuckDB без GUI.
- В аудитории нужно заранее установить.

### Когда использовать

Использовать, если нужно:

- показать SQL как отдельный навык;
- визуально подключиться к базе;
- открыть SQLite/DuckDB-файл;
- дать альтернативу MySQL Workbench.

### Когда не использовать

Если занятие полностью построено в JupyterLab и SQL не является центральной темой.

# 8. R-инструменты

## 8.1. RStudio Desktop

### Назначение

RStudio Desktop — IDE для R и Python от Posit. В учебном комплекте подходит для:

- запуска R-скриптов;
- работы с `ggplot2`;
- анализа таблиц в R;
- демонстрации Python → R через CSV/Excel/Parquet/DuckDB.

Официальная страница Posit описывает RStudio Desktop как open-source IDE для Windows, macOS и Linux, с редактором, отладчиком и инструментами графиков для R и Python.

### Плюсы

- Привычная IDE для R.
- Удобна для R-скриптов.
- Хорошо подходит для `tidyverse`, `readr`, `readxl`, `ggplot2`.
- Есть панели Environment, Files, Plots, Help.
- Хороший выбор, если курс включает R.

### Ограничения

- Для Python-части не так универсален, как VS Code или Positron.
- Нужна отдельная установка R.
- Для R-пакетов нужна предварительная установка.
- Может быть избыточен, если R только демонстрационный.

### Когда использовать

Использовать, если:

- R-часть важна;
- слушатели знакомятся с R;
- нужно показать R-скрипты из папки `r/`.

### Когда не использовать

Если занятие полностью ориентировано на Python, а R нужен только как обзор.

---

## 8.2. Positron

### Назначение

Positron — IDE для data science от Posit, ориентированная на работу с Python и R в единой среде. В учебном комплекте может использоваться как альтернатива VS Code/RStudio для смешанного Python + R workflow.

Официальная страница Positron описывает его как бесплатную data science IDE, объединяющую exploration и production работу в среде для Python и R.

### Плюсы

- Единая среда для Python и R.
- Хорошо подходит для data science workflow.
- Удобен для мостов Python ↔ R.
- Может быть современным вариантом для смешанной аналитики.
- Подходит, если нужно показать будущее направление работы с Python/R.

### Ограничения

- Для многих организаций и преподавателей инструмент может быть новым.
- Нужно заранее проверить установку и стабильность.
- Может быть лишним для базового курса.
- Лицензия и условия использования должны быть проверены организацией.
- Не стоит заменять им JupyterLab на первом занятии без тестирования.

### Когда использовать

Использовать, если:

- нужно единое пространство Python + R;
- группа уже знакома с базовыми IDE;
- есть время на демонстрацию современного инструмента;
- лектор заранее проверил установку.

### Когда не использовать

Если уровень слушателей низкий и нужно минимизировать число новых интерфейсов.

# 10. Методическая рекомендация для занятия

## 10.1. Не перегружать слушателей инструментами

Для начинающей группы не стоит одновременно давать:

```text
JupyterLab + VS Code + DataSphere + Cloud.ru + SQLite + DuckDB + DBeaver + RStudio + Positron
```

Лучше разделить:

### Основной маршрут

```text
JupyterLab
Python
pandas
локальные файлы
DuckDB на обзорном уровне
```

### Дополнительный маршрут

```text
VS Code
DBeaver
RStudio / Positron
Yandex DataSphere / Cloud.ru ML Space
```

---

## 10.2. Как объяснить выбор стека слушателям

Можно использовать такую формулировку:

> На занятии мы берем локальный стек, потому что он работает без интернета и не зависит от облачных аккаунтов. JupyterLab нужен для пошагового обучения, VS Code — для полноценной структуры проекта, DuckDB и SQLite — для локального SQL, а офисные пакеты — для проверки CSV и Excel. Облачные платформы DataSphere и Cloud.ru ML Space полезны в корпоративных и ML-сценариях, но требуют доступа, бюджета и согласования безопасности.

# 11. Итоговая таблица по инструментам

| Инструмент | Назначение | Плюсы | Ограничения | Когда использовать |
|---|---|---|---|---|
| JupyterLab | Ноутбуки и обучение Python | Интерактивность, Markdown + код + графики | Порядок ячеек, Kernel, менее удобен для больших проектов | Основной учебный инструмент |
| VS Code | IDE для проекта | `.ipynb`, `.py`, терминал, R, Git | Нужны расширения и настройка интерпретатора | Когда нужно показать проектную работу |
| Yandex DataSphere | Облачная DS/ML-среда | Jupyter, облачные ресурсы, российская платформа | Интернет, аккаунт, тарифы, ИБ | Если нужна облачная среда |
| Cloud.ru ML Space | ML-платформа полного цикла | ML workflow, GPU/инфраструктура, российский контур | Избыточна для базового pandas, нужны доступы | Для ML/корпоративных сценариев |
| LibreOffice | Офисный пакет | Бесплатный, open source, офлайн | Возможны отличия от Excel | Просмотр CSV/XLSX |
| Р7-Офис | Российский офисный пакет | Импортозамещение, офисные форматы | Лицензии, проверка совместимости | Если принят в организации |
| МойОфис | Российский офисный пакет | Российская экосистема, документы/таблицы/презентации | Лицензии, редакции | Если принят в организации |
| SQLite | Локальная SQL-база | Просто, без сервера, офлайн | Не для тяжелой аналитики | Базовый SQL |
| DuckDB | Локальная аналитическая SQL-база | Быстро, Python/R, Parquet, SQL | Не клиент-серверная OLTP-СУБД | Аналитика и обмен Python ↔ R |
| DBeaver | SQL-клиент | GUI, много баз, SQL | Интерфейс может быть сложным | Визуальная SQL-практика |
| RStudio | IDE для R | Удобно для R и графиков | Отдельная среда от Python | R-часть курса |
| Positron | IDE для Python + R | Единая data science среда | Новый инструмент, нужна проверка | Смешанный Python/R workflow |
