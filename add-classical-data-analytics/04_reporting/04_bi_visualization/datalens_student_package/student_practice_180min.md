# Практическая работа в Yandex DataLens

## Модель данных, связи и интерактивный дашборд службы поддержки

## Цель

Создать в DataLens файловое подключение, настроить связи между таблицами, проверить модель данных, построить основной BI-датасет, набор чартов и дашборд с селекторами.

## Итоговый результат

В вашем воркбуке должны быть:

- подключение `Support Service Files`;
- датасет `Support Model — Raw Joins`;
- датасет `Support Service — BI Mart`;
- четыре KPI;
- минимум четыре аналитических чарта;
- дашборд `Support Service Dashboard`;
- вкладки `Операционный обзор` и `Лаборатория гипотез`;
- селекторы периода, региона и канала.

## Исходные файлы

Основные:

```text
data/raw/support_tickets.csv
data/raw/customers.csv
data/raw/regions.csv
data/bi/support_service_datalens.csv
data/bi/hypothesis_summary_datalens.csv
```

Дополнительные:

```text
data/bi/daily_forecast_datalens.csv
data/bi/forecast_metrics_datalens.csv
```

# Часть 1. Рабочее пространство и подключение

## Шаг 1. Создайте воркбук

1. Откройте DataLens.
2. Перейдите в раздел **Коллекции и воркбуки**.
3. Создайте воркбук.
4. Назовите его `Support Service — Фамилия`.

## Шаг 2. Создайте файловое подключение

1. В воркбуке нажмите **Создать → Подключение**.
2. Выберите источник **Файлы**.
3. Загрузите пять основных CSV.
4. Для каждого CSV проверьте:
   - кодировка `utf-8-sig` или `utf-8`;
   - разделитель «Запятая»;
   - первая строка используется как заголовок.
5. Просмотрите превью.
6. Сохраните подключение как `Support Service Files`.

### Самопроверка

- [ ] каждый файл отображается отдельной таблицей;
- [ ] названия столбцов читаются корректно;
- [ ] данные не открылись одной колонкой;
- [ ] кириллица отображается без искажений.

# Часть 2. Датасет из связанных таблиц

## Шаг 3. Создайте датасет

1. Нажмите **Создать → Датасет**.
2. Добавьте подключение `Support Service Files`.
3. Перетащите `support_tickets` на рабочую область первой.
4. Добавьте `customers` и `regions`.

## Шаг 4. Настройте связь с customers

- тип: `left`;
- левое поле: `support_tickets.customer_id`;
- правое поле: `customers.customer_id`.

## Шаг 5. Настройте связь с regions

- тип: `left`;
- левое поле: `support_tickets.region_id`;
- правое поле: `regions.region_id`.

Для учебной проверки модели отключите **Оптимизировать связь**, чтобы JOIN выполнялся независимо от набора полей в чарте.

## Шаг 6. Проверьте типы полей

- идентификаторы — строки и измерения;
- `created_at` — дата и время;
- времена и оценка — числовые поля;
- канал, категория, приоритет, сегмент, регион — измерения.

Сохраните датасет как `Support Model — Raw Joins`.

## Шаг 7. Проверьте модель

Создайте два индикатора:

```text
COUNT([ticket_id])
COUNTD([ticket_id])
```

Ожидается:

- записей: 1510;
- уникальных обращений: 1500.

Создайте таблицу:

- измерение: `region_name`;
- показатель: `COUNTD([ticket_id])`.

Для пустого региона ожидается 28 уникальных обращений.

### Что это означает

- исходный журнал содержит повторные `ticket_id`;
- часть `region_id` отсутствует в справочнике;
- `LEFT JOIN` сохранил обращения с неизвестным регионом;
- для KPI количества обращений нужен `COUNTD`.

# Часть 3. Основной BI-датасет

## Шаг 8. Создайте датасет на витрине

1. Создайте новый датасет.
2. Добавьте таблицу `support_service_datalens`.
3. Сохраните как `Support Service — BI Mart`.

Контроль:

- 1500 строк;
- 1500 уникальных `ticket_id`;
- одна строка соответствует одному обращению.

## Шаг 9. Проверьте типы

Назначьте тип «Дата» полям:

- `created_date`;
- `week_start`;
- `month_start`;
- `registration_date`.

Проверьте числовые поля:

- `first_response_min`;
- `resolution_hours`;
- `satisfaction_score`;
- `sla_breached`;
- `record_count`.

## Шаг 10. Создайте вычисляемые поля

### Количество обращений

```text
COUNTD([ticket_id])
```

### Средняя оценка

```text
AVG([satisfaction_score])
```

### Среднее время решения, ч

```text
AVG([resolution_hours])
```

### Доля нарушений SLA

```text
AVG([sla_breached])
```

Установите процентный формат для доли SLA.

# Часть 4. Чарты

## Шаг 11. KPI

Создайте четыре индикатора:

1. количество обращений;
2. средняя оценка;
3. среднее время решения;
4. доля нарушений SLA.

Контроль без фильтров:

| KPI | Ожидаемое значение |
|---|---:|
| обращения | 1500 |
| средняя оценка | около 4,13 |
| среднее время решения | около 20,39 ч |
| SLA нарушен | около 34,53% |

## Шаг 12. Динамика обращений

- тип: линейная диаграмма;
- X: `created_date`;
- Y: `Количество обращений`;
- название: `Динамика обращений по дням`.

## Шаг 13. Оценка по каналам

- тип: столбчатая диаграмма;
- измерение: `channel`;
- показатель: `Средняя оценка`;
- сортировка: по убыванию;
- название: `Средняя оценка по каналам`.

## Шаг 14. Время решения по категориям

- тип: столбчатая диаграмма;
- измерение: `category`;
- показатель: `Среднее время решения, ч`;
- сортировка: по убыванию;
- название: `Среднее время решения по категориям`.

## Шаг 15. Связь времени решения и оценки

- тип: точечная диаграмма;
- X: `resolution_hours`;
- Y: `satisfaction_score`;
- цвет: `channel`;
- детализация: `ticket_id`;
- название: `Время решения и оценка клиента`.

# Часть 6. Лаборатория гипотез

## Шаг 19. Создайте визуальную часть H1

Создайте вкладку `Лаборатория гипотез`.

Вопрос:

```text
Отличается ли средняя оценка между каналами chat и email?
```

Создайте столбчатый чарт:

- измерение: `channel`;
- показатель: `Средняя оценка`;
- фильтр: `chat`, `email`.

## Шаг 20. Добавьте статистическую таблицу

1. Создайте датасет на `hypothesis_summary_datalens.csv`.
2. Создайте таблицу с полями:
   - `group_name`;
   - `sample_size`;
   - `mean_value`;
   - `median_value`;
   - `p_value`;
   - `cohens_d_a_minus_b`;
   - `decision`;
   - `effect_magnitude`.
3. Установите фильтр `hypothesis_id = H1`.
4. Добавьте таблицу на вкладку гипотез.

## Шаг 21. Добавьте интерпретацию

```text
В полной очищенной выборке средняя оценка chat выше средней оценки email. Различие статистически значимо, размер эффекта большой. Эти наблюдательные данные не доказывают, что канал является единственной причиной различия.

После изменения селекторов статистический тест нужно пересчитать на том же срезе.
```

# Типовые ошибки

| Ошибка | Исправление |
|---|---|
| строки потерялись после связи | проверьте, не выбран ли `INNER JOIN` |
| количество обращений выше 1500 | используйте `COUNTD`, проверьте JOIN и дубли |
| регион пустой | это несовпавший ключ; `LEFT JOIN` сохранил факт |
| дата сортируется как текст | назначьте тип «Дата» |
| SLA отображается как 0,345 | примените процентный формат |
| поле не доступно селектору | создайте его на уровне датасета |
| селектор не влияет на чарт | проверьте связь виджета и область действия |
| p-value не меняется от фильтра | статистическая таблица рассчитана для полной выборки |
