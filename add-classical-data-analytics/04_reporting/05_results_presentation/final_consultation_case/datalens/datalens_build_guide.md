# Построение аналитического приложения в Yandex DataLens

## 1. Источник

Используйте `data/processed/ecommerce_datamart.csv`. Одна строка соответствует одному заказу. Витрина уже содержит справочные признаки, финансовые показатели, флаги возврата и нарушения SLA.

## 2. Проверка датасета

После загрузки проверьте типы:

- `order_date` - дата;
- `latitude`, `longitude` - дробные числа;
- `discount_pct`, `margin_pct` - дробные числа с процентным форматом;
- флаги `is_returned`, `late_flag`, `sla_eligible` - целые числа или логические значения;
- `recognized_revenue`, `gross_profit` - показатели с агрегацией SUM;
- идентификаторы и категории - измерения без суммирования.

## 3. Вычисляемые поля

```text
Количество заказов = COUNTD([order_id])
Количество клиентов = COUNTD([customer_id])
Выручка = SUM([recognized_revenue])
Валовая прибыль = SUM([gross_profit])
Маржинальность = SUM([gross_profit]) / SUM([recognized_revenue])
Доля возвратов = SUM([is_returned]) / COUNTD([order_id])
Доля отмен = SUM([is_cancelled]) / COUNTD([order_id])
Доля нарушений SLA = SUM([late_flag]) / SUM([sla_eligible])
Средний чек = SUM([recognized_revenue]) / COUNTD_IF([order_id], [is_delivered] = 1)
```

Для деления добавьте защиту от нуля, если выбранный фильтр может дать пустой набор.

## 4. Вкладка «Управленческий обзор»

1. Индикатор: Выручка.
2. Индикатор: Валовая прибыль.
3. Индикатор: Маржинальность.
4. Индикатор: Доля нарушений SLA.
5. Линейный график: `order_month` -> Выручка и Валовая прибыль.
6. Столбчатая диаграмма: `category` -> Выручка.
7. Карта: `latitude`, `longitude`; размер -> Количество заказов; цвет -> Доля нарушений SLA.
8. Таблица: регион, заказы, выручка, прибыль, SLA, возвраты.

## 5. Вкладка «Сегменты и риски»

- категории по возвратам;
- регионы по SLA;
- каналы продаж по маржинальности;
- продукты по `abc_xyz` после присоединения `abc_xyz_products.csv` либо через отдельный датасет;
- клиенты по RFM-сегментам через `rfm_segments.csv`;
- таблица заказов с отрицательной маржой.

## 6. Селекторы

- период;
- регион;
- категория;
- канал;
- тип доставки;
- статус заказа;
- кампания;
- признак высокого дисконта.

Проверьте связи селекторов с каждым чартом. При использовании нескольких датасетов поля можно связывать через алиасы.

## 8. Публикация и доступ

Для демонстрации на защите достаточно предоставить проверяющему права просмотра. Возможности и расположение команд могут отличаться в зависимости от версии, роли и настроек рабочей области, поэтому перед консультацией проверьте доступ из отдельного браузера или инкогнито-окна.

## 9. Типовые ошибки

| Ошибка | Причина | Проверка |
|---|---|---|
| Выручка завышена | Суммируется повторяющийся уровень данных | Проверить гранулярность и COUNTD(order_id) |
| SLA больше 100% | Неверный знаменатель | Делить late_flag на sla_eligible |
| Маржинальность не совпадает | Усреднение процентов вместо отношения сумм | Использовать SUM(profit)/SUM(revenue) |
| Селектор не влияет на чарт | Нет связи или поле отсутствует в датасете | Проверить связи виджетов |
| Карта пустая | Неверные типы координат | Проверить дробный тип latitude/longitude |
