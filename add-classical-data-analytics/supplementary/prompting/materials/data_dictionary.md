# Data dictionary: sales_sample.csv

| Поле | Тип | Назначение | Что можно проверить |
|---|---|---|---|
| order_id | string | идентификатор заказа | дубликаты, уникальность |
| order_date | date/string | дата заказа | преобразование в дату, некорректные даты |
| region | string | регион продажи | пропуски, группировки |
| sales_channel | string | канал продаж | сравнение online/offline/marketplace/partner |
| product_category | string | категория товара | пробелы, регистр, пропуски |
| customer_segment | string | клиентский сегмент | сравнение B2C/B2B/SMB/Enterprise |
| quantity | integer | количество единиц | значения <= 0 |
| unit_price | float | цена за единицу | значения <= 0 |
| discount_rate | float | скидка в долях от 0 до 1 | значения вне диапазона 0–1 |
| revenue | float | выручка | отрицательные значения, динамика |
| cost | float | себестоимость | маржинальность |
| return_flag | integer | признак возврата, 0/1 | доля возвратов |

## Основные аналитические показатели

- Выручка: `sum(revenue)`.
- Количество заказов: `nunique(order_id)`.
- Средний чек: `sum(revenue) / nunique(order_id)`.
- Средняя скидка: `mean(discount_rate)`.
- Доля возвратов: `mean(return_flag)`.
- Валовая маржа: `sum(revenue - cost)`.

## Важное ограничение

Даже если рост скидок и изменение выручки наблюдаются одновременно, это не доказывает причинность. Для аккуратной интерпретации нужно сравнивать похожие периоды, категории, каналы и регионы, а также учитывать изменения количества заказов, среднего чека и возвратов.
