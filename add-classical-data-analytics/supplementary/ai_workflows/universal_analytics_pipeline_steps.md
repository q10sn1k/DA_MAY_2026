# Универсальный аналитический пайплайн по шагам

Этот файл описывает общий порядок аналитической работы. Его можно применять к разным источникам данных: CSV, Excel, SQL-таблицам, данным из API, выгрузкам CRM, логам, опросам, финансовым таблицам и другим наборам данных.

Пайплайн построен так, чтобы аналитик двигался не хаотично, а последовательно: от постановки вопроса к проверке данных, расчётам, визуализации, интерпретации и итоговому выводу.

---

## Шаг 1. Определить цель анализа

Сначала нужно понять, зачем выполняется анализ.

Плохая формулировка:

```text
Посмотреть данные.
```

Хорошая формулировка:

```text
Выявить, какие категории товаров дают основную выручку за последние 12 месяцев.
```

или:

```text
Определить, какие факторы связаны с оттоком клиентов.
```

На этом шаге нужно зафиксировать:

- что именно анализируется;
- зачем нужен результат;
- кто будет использовать вывод;
- какое решение может быть принято по итогам анализа.

**Результат шага:** сформулирована цель анализа.

---

## Шаг 2. Сформулировать аналитические вопросы

Цель нужно разложить на конкретные вопросы.

Примеры аналитических вопросов:

- какие категории дают наибольшую долю выручки;
- какие клиенты покупают чаще других;
- какие товары продаются хуже всего;
- как меняется показатель по месяцам;
- есть ли различия между регионами;
- какие признаки связаны с целевым показателем;
- где находятся аномалии или выбросы.

Аналитический вопрос должен быть проверяемым по данным.

Плохой вопрос:

```text
Почему бизнес работает плохо?
```

Лучший вариант:

```text
В каких регионах снизилось количество заказов по сравнению с предыдущим месяцем?
```

**Результат шага:** составлен список вопросов, на которые должен ответить анализ.

Перед работой с данными нужно понять, в каком виде должен быть итог.

Возможные результаты:

- таблица с агрегированными показателями;
- графики;

- модель или прогноз.

Нужно заранее определить формат результата. Это помогает не делать лишние расчёты и не уходить в случайное исследование данных.

**Результат шага:** определён формат итогового результата.

```python
df.shape
```

**Результат шага:** проверено количество строк и столбцов.

```python
df.head()
```

## Шаг 8. Изучить типы данных

Нужно проверить, какие типы данных определены для столбцов.

```python
df.info()
```

Типовые типы данных:

- `int` — целые числа;
- `float` — числа с дробной частью;
- `object` — текстовые значения;
- `datetime` — даты и время;
- `bool` — логические значения.

Тип данных влияет на то, какие операции можно выполнять.

Например:

- по числам можно считать среднее;
- по датам можно строить динамику;
- по категориям можно считать частоты;
- по тексту можно искать слова и шаблоны.

Если дата прочиталась как текст, временной анализ будет некорректным, пока столбец не преобразован.

**Результат шага:** определены типы данных и возможные проблемы с ними.

## Шаг 9. Проверить названия столбцов

Названия столбцов должны быть понятными и удобными для работы.

Проблемы в названиях:

- пробелы в начале или конце;
- разные языки;
- слишком длинные названия;
- спецсимволы;
- одинаковые названия;
- непонятные сокращения;
- разный стиль записи.

Пример приведения названий к единому стилю:

```python
df.columns = df.columns.str.strip().str.lower().str.replace(' ', '_')
```

До:

```text
Customer Name
Order Date
Total Revenue
```

После:

```text
customer_name
order_date
total_revenue
```

**Результат шага:** названия столбцов приведены к понятному и единому формату.

## Шаг 10. Проверить пропуски

Пропуски — это отсутствующие значения.

Проверка количества пропусков:

```python
df.isna().sum()
```

Проверка доли пропусков:

```python
df.isna().mean() * 100
```

Важно понять не только количество пропусков, но и причину их появления.

Возможные причины:

- данные не были собраны;
- поле необязательно;
- произошла ошибка выгрузки;
- значение отсутствует по смыслу;
- данные были удалены из-за ограничений доступа.

Пропуски нельзя всегда автоматически удалять. Иногда пропуск сам является важным аналитическим сигналом.

**Результат шага:** выявлены пропуски и выбрана стратегия работы с ними.

---

## Шаг 11. Обработать пропуски

После диагностики нужно решить, что делать с пропусками.

Возможные варианты:

- удалить строки с пропусками;
- удалить столбец с большим количеством пропусков;
- заполнить пропуски средним значением;
- заполнить медианой;
- заполнить модой;
- заполнить специальным значением, например `unknown`;
- оставить пропуски, если они имеют аналитический смысл.

Пример удаления строк:

```python
df = df.dropna()
```

Пример заполнения текстового поля:

```python
df['category'] = df['category'].fillna('unknown')
```

Пример заполнения числового поля медианой:

```python
df['price'] = df['price'].fillna(df['price'].median())
```

**Результат шага:** пропуски обработаны осознанным способом.

## Шаг 12. Проверить дубликаты

Дубликаты — это повторяющиеся строки или повторяющиеся сущности.

Проверка полных дубликатов:

```python
df.duplicated().sum()
```

Удаление полных дубликатов:

```python
df = df.drop_duplicates()
```

Иногда полных дубликатов нет, но есть смысловые дубликаты.

Например:

```text
Иванов Иван
Иван Иванов
Ivan Ivanov
```

Для человека это может быть один клиент, но таблица воспринимает такие записи как разные значения.

**Результат шага:** проверены и обработаны дубликаты.

```python
df['month'] = df['date'].dt.to_period('M')
```

```python
df['avg_check'] = df['revenue'] / df['orders']
```

**Результат шага:** созданы признаки, которые помогают ответить на аналитические вопросы.

## Шаг 18. Построить агрегированные таблицы

Агрегация нужна, чтобы перейти от отдельных строк к сводным показателям.

Пример группировки:

```python
df.groupby('category')['revenue'].sum()
```

Пример нескольких показателей:

```python
df.groupby('category').agg({
    'revenue': 'sum',
    'orders': 'count',
    'price': 'mean'
})
```

Агрегация помогает ответить на вопросы:

- сколько заказов в каждой категории;
- какая категория даёт больше выручки;
- какой средний чек по регионам;
- как меняется показатель по месяцам;

## Шаг 19. Построить визуализации

Визуализация нужна не для украшения, а для проверки структуры данных и объяснения вывода.

Типовые графики:

- линейный график для динамики;

## Шаг 20. Проверить выбросы и аномалии

Выброс — это значение, которое сильно отличается от остальных.

Примеры:

- слишком высокая цена;
- отрицательная выручка;
- слишком большое количество заказов;
- дата вне периода анализа;
- рейтинг вне допустимого диапазона.

Выбросы нельзя автоматически удалять. Сначала нужно понять их природу.

Возможные варианты:

- это ошибка ввода;
- это ошибка выгрузки;
- это редкое, но реальное событие;
- это мошенничество;
- это особый сегмент;
- это технический сбой.

**Результат шага:** выбросы выявлены и описаны.

## Шаг 21. Проверить связи между признаками

На этом этапе анализируются отношения между переменными.

Примеры вопросов:

- связан ли размер скидки с количеством заказов;
- зависит ли выручка от региона;
- отличаются ли группы клиентов по среднему чеку;
- есть ли связь между рейтингом и продажами;
- изменяется ли показатель во времени.

Для числовых признаков можно использовать корреляцию:

```python
df.corr(numeric_only=True)
```

Важно: корреляция не доказывает причинно-следственную связь. Если два показателя связаны, это не означает, что один обязательно вызывает другой.

**Результат шага:** выявлены возможные связи, которые требуют интерпретации.

## Шаг 23. Проверить корректность расчётов

```python
summary['revenue'].sum()
```

Если суммы должны совпадать, но не совпадают, нужно найти причину.

**Результат шага:** подтверждена корректность расчётов.

## Шаг 24. Интерпретировать результаты

Интерпретация — это объяснение смысла результата.

Недостаточно написать:

```text
Категория A имеет 40% выручки.
```

Нужно объяснить:

```text
Категория A формирует 40% выручки, поэтому её изменение сильнее всего повлияет на общий результат. При этом нужно проверить маржинальность, потому что высокая выручка не всегда означает высокую прибыль.
```

Хороший аналитический вывод содержит:

- факт;
- числовое подтверждение;
- объяснение смысла;
- ограничение;
- возможное действие.

**Результат шага:** подготовлены содержательные аналитические выводы.

## Шаг 25. Сформулировать ограничения анализа

Любой анализ имеет ограничения.

Примеры ограничений:

- данные покрывают не весь период;
- часть значений отсутствует;
- источник может содержать ошибки;
- выборка нерепрезентативна;
- нет данных о внешних факторах;
- невозможно доказать причинность;
- часть категорий была объединена;
- данные были очищены по выбранным правилам.

Ограничения нужно указывать честно. Они не ослабляют анализ, а делают его корректным.

**Результат шага:** описаны границы применимости выводов.

---

## Шаг 26. Подготовить рекомендации

Рекомендации должны следовать из данных.

Плохая рекомендация:

```text
Нужно улучшить продажи.
```

Хорошая рекомендация:

```text
Сначала следует проверить причины снижения продаж в регионе X, потому что за последние три месяца количество заказов там снизилось на 18%, тогда как в остальных регионах показатель оставался стабильным.
```

Рекомендация должна быть:

- конкретной;
- связанной с результатами анализа;
- проверяемой;
- применимой в рабочем процессе;
- ограниченной рамками данных.

**Результат шага:** сформулированы практические рекомендации.

## Шаг 27. Подготовить итоговый отчёт

Итоговый отчёт должен быть понятен человеку, который не писал код.

Структура отчёта:

1. Цель анализа.
2. Использованные данные.
3. Краткое описание подготовки данных.
4. Основные расчёты.
5. Ключевые графики.
6. Основные выводы.
7. Ограничения анализа.
8. Рекомендации.
9. Приложения или ссылки на файлы.

В отчёте не нужно показывать весь технический код. Код остаётся в ноутбуке или скрипте. В отчёт выносится то, что помогает принять решение.

**Результат шага:** подготовлен итоговый аналитический отчёт.

## Шаг 29. Проверить воспроизводимость

Анализ должен быть воспроизводимым. Это означает, что другой человек может повторить шаги и получить тот же результат.

Проверить нужно:

- есть ли исходные данные;
- понятно ли, как запустить код;
- указаны ли библиотеки;
- сохранён ли порядок шагов;
- не зависят ли расчёты от ручных действий;
- есть ли описание результата.

Если используется Python, полезно сохранить список библиотек:

```bash
pip freeze > requirements.txt
```

Если используется Jupyter Notebook, нужно выполнить ноутбук сверху вниз и убедиться, что ошибки не возникают.

**Результат шага:** анализ можно повторить без ручного восстановления логики.

# Главное правило аналитика

Аналитический пайплайн должен отвечать не на вопрос «какой код был написан», а на вопрос «какая задача решалась, какие данные использовались, как они были проверены, какой расчёт выполнен и какой вывод можно сделать».

Код является инструментом. Основной результат аналитической работы — проверяемый вывод, основанный на данных.
