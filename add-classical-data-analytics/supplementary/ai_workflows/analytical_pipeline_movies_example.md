# Полный аналитический пайплайн на примере анализа фильмов на стриминговых платформах

Этот файл объясняет полный аналитический пайплайн, который был выполнен в ноутбуке `example.ipynb` на данных `MoviesOnStreamingPlatforms.csv`. Инструкция написана простым языком и рассчитана на новичка, который только начинает работать с анализом данных в Python и Jupyter Notebook.

В примере анализируется набор данных о фильмах на стриминговых платформах. В таблице есть названия фильмов, год выпуска, возрастной рейтинг, оценка Rotten Tomatoes и признаки доступности фильма на платформах Netflix, Hulu, Prime Video и Disney+.

Главная логика аналитической работы выглядит так:

```text
данные → задача → вопрос → загрузка → первичный осмотр → очистка → признаки → анализ → визуализация → интерпретация → ограничения → вывод
```

Аналитик не просто строит графики. Он проходит последовательный путь: понимает задачу, проверяет качество данных, готовит таблицу, рассчитывает показатели, визуализирует результат и формулирует выводы с учётом ограничений.

## 1. Что такое аналитический пайплайн

**Аналитический пайплайн** — это последовательность действий, с помощью которой исходные данные превращаются в осмысленный аналитический результат.

Если сказать проще, пайплайн отвечает на вопрос:

```text
Что нужно сделать с таблицей, чтобы из неё получить проверяемый вывод?
```

В реальной работе нельзя сразу строить график и делать вывод. Сначала нужно понять, какие данные есть, какие столбцы нужны, где есть пропуски, какие типы данных используются, какие признаки нужно преобразовать и какие ограничения есть у результата.

В данном примере пайплайн состоит из следующих этапов:

1. постановка аналитической задачи;
2. загрузка данных;
3. первичный осмотр таблицы;
4. удаление лишних столбцов;
5. обработка пропусков;
6. преобразование типов данных;
7. разведочный анализ данных;
8. расчёт дополнительных признаков;
9. анализ платформенного охвата;
10. ABC- и XYZ-сегментация;
11. адаптированный RFM-анализ;
12. построение обзорного дашборда;
13. формулировка выводов;
14. фиксация ограничений анализа.

## 2. Постановка аналитической задачи

Перед началом кода нужно понять, зачем выполняется анализ.

В нашем случае рабочую задачу можно сформулировать так:

```text
Проанализировать каталог фильмов на стриминговых платформах и определить, как распределены фильмы по платформам, возрастным рейтингам, годам выпуска, оценкам качества и широте доступности.
```

Эта задача может быть полезна в нескольких рабочих ситуациях:

- аналитик стримингового сервиса сравнивает объём библиотек разных платформ;
- маркетолог оценивает, какие возрастные категории представлены сильнее;
- продуктовая команда изучает, насколько каталог современный;
- контент-аналитик определяет, какие фильмы доступны только на одной платформе;
- менеджер хочет получить обзорную картину по каталогу без ручного просмотра всей таблицы.

Из этой задачи появляются аналитические вопросы:

```text
Какая платформа содержит больше всего фильмов?
Какие возрастные рейтинги встречаются чаще всего?
В какие десятилетия было выпущено больше всего фильмов?
Как распределены рейтинги Rotten Tomatoes?
Сколько фильмов доступны сразу на нескольких платформах?
Какие фильмы можно считать наиболее широко доступными?
Какие фильмы доступны только на одной платформе?
```

Хорошая аналитическая работа начинается именно с вопросов. Если вопрос не сформулирован, график может быть красивым, но его смысл будет неясен.

## 6. Проверка смысла строк и столбцов

Перед очисткой важно понять, что означает строка и что означает столбец.

В данном датасете:

```text
строка = один фильм;
столбец = один признак фильма.
```

Например:

- `Title` — название фильма;
- `Year` — год выпуска;
- `Age` — возрастной рейтинг;
- `Rotten Tomatoes` — оценка качества;
- `Netflix`, `Hulu`, `Prime Video`, `Disney+` — бинарные признаки наличия фильма на платформе.

Бинарный признак означает, что значение обычно принимает два варианта:

```text
1 = фильм есть на платформе
0 = фильма нет на платформе
```

Это важно для дальнейшего анализа. Если в столбцах платформ стоят нули и единицы, количество фильмов на платформе можно посчитать простой суммой.

Например:

```python
df['Netflix'].sum()
```

Эта команда считает, сколько строк имеют значение `1` в столбце `Netflix`.

## 7. Удаление лишних столбцов

В ноутбуке удаляются столбцы:

```python
df.drop(columns=['Unnamed: 0', 'ID', 'Type'], inplace=True)
```

Эта команда удаляет столбцы, которые не используются в анализе.

Почему их можно удалить:

- `Unnamed: 0` обычно возникает при сохранении CSV из DataFrame вместе с индексом;
- `ID` может быть техническим идентификатором записи;
- `Type` в текущем анализе не используется для расчётов и интерпретации.

После удаления таблица становится проще. В ней остаются только те признаки, которые реально участвуют в анализе.

Для учебного кода можно использовать более безопасный стиль без `inplace=True`:

```python
df = df.drop(columns=['Unnamed: 0', 'ID', 'Type'])
```

Такой вариант проще контролировать: результат операции явно присваивается обратно в переменную `df`.

## 8. Обработка пропусков в возрастном рейтинге

В столбце `Age` есть пропуски. В исходных данных их было:

```text
4177 пропусков
```

Это примерно 43,9% строк.

В ноутбуке пропуски заменяются значением `Unknown`:

```python
df['Age'].fillna('Unknown', inplace=True)
```

Смысл этой операции простой: если возрастной рейтинг не указан, мы не удаляем фильм из таблицы, а явно помечаем неизвестное значение.

Для начинающего аналитика это важный принцип. Пропуск не всегда нужно удалять. Иногда пропуск сам является важной информацией.

В данном случае большое количество `Unknown` показывает ограничение данных: почти у половины фильмов возрастной рейтинг отсутствует. Поэтому любые выводы о возрастных категориях нужно делать осторожно.

Более современный и понятный вариант записи:

```python
df['Age'] = df['Age'].fillna('Unknown')
```

После этого в столбце `Age` не будет пустых значений, а неизвестные рейтинги будут видны как отдельная категория.

## 9. Очистка рейтинга Rotten Tomatoes

Столбец `Rotten Tomatoes` в исходном файле хранится как текст.

Пример значения:

```text
98/100
```

Для расчётов такое значение неудобно. Python воспринимает его как строку, а не как число.

Поэтому сначала удаляется часть `/100`:

```python
df['Rotten Tomatoes'] = df['Rotten Tomatoes'].str.replace('/100', '')
```

После этого значение `98/100` превращается в строку `98`.

Затем столбец преобразуется в числовой тип:

```python
df['Rotten Tomatoes'] = pd.to_numeric(df['Rotten Tomatoes'], errors='coerce')
```

Параметр:

```python
errors='coerce'
```

означает: если значение нельзя преобразовать в число, заменить его на `NaN`.

`NaN` — это специальное обозначение пропущенного числового значения.

## 10. Заполнение пропусков в Rotten Tomatoes медианой

В исходном столбце `Rotten Tomatoes` было 7 пропусков. После преобразования к числу они обрабатываются через медиану.

```python
median_rating = df['Rotten Tomatoes'].median()
df['Rotten Tomatoes'].fillna(median_rating, inplace=True)
```

Медиана — это значение, которое делит упорядоченный ряд пополам. В этом датасете медиана рейтинга равна:

```text
52
```

Почему используется медиана, а не среднее значение?

Среднее может сильнее зависеть от выбросов. Медиана часто устойчивее, если распределение не идеально симметрично или есть крайние значения.

Для учебного кода можно записать так:

```python
median_rating = df['Rotten Tomatoes'].median()
df['Rotten Tomatoes'] = df['Rotten Tomatoes'].fillna(median_rating)
```

После этого рейтинг становится числовым столбцом, с которым можно считать минимум, максимум, среднее, медиану и строить гистограмму.

## 12. Разведочный анализ данных

После подготовки начинается разведочный анализ данных, или **EDA**.

EDA расшифровывается как **Exploratory Data Analysis**. На русском языке это обычно называют разведочным анализом данных.

Цель EDA — понять структуру данных, увидеть основные распределения, найти закономерности, заметить аномалии и подготовить основу для выводов.

В ноутбуке рассматриваются пять направлений:

1. количество фильмов на каждой платформе;
2. распределение фильмов по возрастным рейтингам;
3. распределение фильмов по годам выпуска;
4. распределение оценок Rotten Tomatoes;
5. пересечения между платформами.

EDA не является финальным доказательством причинно-следственных связей. Это первичный аналитический обзор. Он показывает, как устроены данные и какие вопросы стоит исследовать дальше.

```python
platform_counts = {
```

```python
plt.figure(figsize=(6,4))
```

## 14. Анализ возрастных рейтингов

Распределение возрастных рейтингов считается через `value_counts()`.

```python
age_counts = df['Age'].value_counts()
```

Эта команда считает, сколько раз встречается каждое значение в столбце `Age`.

В результате получены категории:

```text
Unknown: 4177
18+: 2276
7+: 1090
13+: 998
all: 698
16+: 276
```

График строится так:

```python
plt.figure(figsize=(7,4))
plt.bar(age_counts.index, age_counts.values)
plt.title("Распределение фильмов по возрастному рейтингу")
plt.xlabel("Возрастной рейтинг")
plt.ylabel("Количество фильмов")
plt.xticks(rotation=45, ha='right')
plt.show()
```

Главный вывод: самая большая категория — `Unknown`. Это означает, что в данных много фильмов без указанного возрастного рейтинга.

Содержательный вывод нужно формулировать осторожно. Нельзя сказать, что каталог в основном состоит из фильмов без рейтинга. Корректнее сказать: в датасете для значительной части фильмов возрастной рейтинг не указан.

Если исключить `Unknown`, наиболее заметна категория `18+`, затем идут `7+` и `13+`.

## 15. Анализ распределения по годам выпуска

Для анализа годов выпуска в ноутбуке создаётся новый столбец `Decade`.

```python
df['Decade'] = (df['Year'] // 10) * 10
```

Эта формула переводит год в десятилетие.

Примеры:

```text
2019 → 2010
2001 → 2000
1995 → 1990
```

Затем считается количество фильмов по десятилетиям:

```python
decade_counts = df['Decade'].value_counts().sort_index()
```

`value_counts()` считает количество фильмов в каждом десятилетии.

`sort_index()` сортирует десятилетия по порядку.

Результат показывает, что особенно много фильмов относится к 2000-м, 2010-м и 2020-м годам. Больше всего фильмов в датасете относится к 2010-м годам:

```text
2010-е: 5359 фильмов
2000-е: 1294 фильма
2020-е: 1189 фильмов
```

Интерпретация: стриминговые каталоги в датасете сильнее представлены современным контентом. Старые фильмы тоже есть, но их заметно меньше.

Ограничение: это распределение отражает состав конкретного датасета, а не всю историю кинопроизводства и не обязательно полные каталоги платформ на текущую дату.

## 16. Анализ рейтингов Rotten Tomatoes

После очистки `Rotten Tomatoes` стал числовым столбцом.

В ноутбуке рассчитываются базовые статистики:

```python
ratings = df['Rotten Tomatoes']

print("Мин:", ratings.min())
print("Макс:", ratings.max())
print("Средний:", ratings.mean())
print("Медиана:", ratings.median())
```

Полученные значения:

```text
минимум: 10
максимум: 98
среднее: около 53,54
медиана: 52
```

Для визуализации строится гистограмма:

```python
plt.figure(figsize=(6,4))
plt.hist(ratings, bins=20, edgecolor='black')
plt.title("Распределение оценок Rotten Tomatoes")
plt.xlabel("Рейтинг Rotten Tomatoes")
plt.ylabel("Число фильмов")
plt.show()
```

Гистограмма показывает, как фильмы распределены по оценкам. Она помогает увидеть, где находится основная масса значений и есть ли крайние значения.

Среднее и медиана близки, поэтому можно осторожно говорить, что типичный рейтинг в датасете находится около 52–54 баллов.

Ограничение: рейтинг Rotten Tomatoes — это только один показатель качества. Он не заменяет анализ жанров, пользовательских оценок, популярности, просмотров или коммерческих показателей.

## 17. Анализ пересечений между платформами

Чтобы понять, на скольких платформах доступен каждый фильм, создаётся столбец `PlatformCount`.

```python
df['PlatformCount'] = df[['Netflix','Hulu','Prime Video','Disney+']].sum(axis=1)
```

Здесь суммируются четыре бинарных столбца по каждой строке.

Если фильм есть только на Netflix, сумма будет равна `1`.

Если фильм есть на Netflix и Hulu, сумма будет равна `2`.

Если фильм есть на всех четырёх платформах, сумма будет равна `4`.

Дальше считается распределение:

```python
platform_count_dist = df['PlatformCount'].value_counts().sort_index()
```

Результат:

```text
1 платформа: 9262 фильма
2 платформы: 245 фильмов
3 платформы: 7 фильмов
4 платформы: 1 фильм
```

Вывод: подавляющее большинство фильмов в датасете представлены только на одной платформе. Пересечения между платформами есть, но они редки.

Это важный аналитический результат. Он показывает, что каталоги платформ в основном не дублируют друг друга на уровне фильмов из данного набора данных.

## 18. ABC-анализ по охвату платформ

В ноутбуке ABC-анализ адаптирован под задачу анализа охвата платформ.

Классический ABC-анализ часто используется в управлении запасами, продажами и ассортиментом. В этом примере он применяется иначе: фильмы делятся на группы по количеству платформ, где они доступны.

Логика такая:

```text
A = фильмы с широким охватом, доступны на 3–4 платформах;
B = фильмы со средним охватом, доступны на 2 платформах;
C = фильмы с узким охватом, доступны только на 1 платформе.
```

Код:

```python
coverage = df['PlatformCount']

A_films = coverage[coverage >= 3].count()
B_films = coverage[coverage == 2].count()
C_films = coverage[coverage == 1].count()
```

Результат:

```text
A: 8 фильмов
B: 245 фильмов
C: 9262 фильма
```

Интерпретация:

```text
Категория C доминирует. Большинство фильмов доступны только на одной платформе.
Категория A минимальна. Фильмов с широким межплатформенным охватом почти нет.
```

Ограничение: это не классический ABC-анализ по выручке или ценности. Это учебная адаптация метода под показатель платформенного охвата.

---

## 19. XYZ-анализ по стабильности охвата

XYZ-анализ в ноутбуке также адаптирован под задачу доступности фильмов.

Логика такая:

```text
X = фильм есть на всех 4 платформах;
Y = фильм есть на 2–3 платформах;
Z = фильм есть только на 1 платформе.
```

Код:

```python
X_films = coverage[coverage == 4].count()
Y_films = coverage[(coverage == 2) | (coverage == 3)].count()
Z_films = coverage[coverage == 1].count()
```

Результат:

```text
X: 1 фильм
Y: 252 фильма
Z: 9262 фильма
```

Смысл интерпретации:

- `X` — максимально широкий охват;
- `Y` — умеренный охват;
- `Z` — минимальный охват.

Большинство фильмов попадает в `Z`. Это означает, что с точки зрения платформенного охвата большая часть фильмов зависит от одной платформы.

Ограничение: в классическом XYZ-анализе обычно оценивается стабильность спроса или потребления. Здесь стабильность интерпретируется учебно — как устойчивость доступности фильма через присутствие на нескольких платформах.

---

## 20. Визуализация ABC и XYZ

Для наглядного сравнения строятся две столбчатые диаграммы рядом.

```python
labels_abc = ['A (3-4 платформы)', 'B (2 платформы)', 'C (1 платформа)']
counts_abc = [A_films, B_films, C_films]

labels_xyz = ['X (4 платформы)', 'Y (2-3 платформы)', 'Z (1 платформа)']

fig, axes = plt.subplots(1, 2, figsize=(10,4))
axes[0].bar(labels_abc, counts_abc)
axes[0].set_title("ABC-анализ")
axes[0].set_ylabel("Число фильмов")

axes[1].bar(labels_xyz, counts_xyz)
axes[1].set_title("XYZ-анализ")

plt.tight_layout()
plt.show()
```

Такая визуализация помогает быстро увидеть дисбаланс. Категории `C` и `Z` существенно больше остальных.

Для управленческого вывода это означает, что каталог сильно фрагментирован по платформам. Если пользователь ищет конкретный фильм, вероятность того, что он доступен сразу на нескольких платформах, низкая.

## 21. RFM-анализ фильмов: адаптация метода

В ноутбуке используется адаптированный RFM-анализ.

Классический RFM-анализ применяется для анализа клиентов:

```text
R = Recency, давность последней покупки;
F = Frequency, частота покупок;
M = Monetary, денежная ценность клиента.
```

В текущем датасете клиентов и покупок нет. Поэтому метод адаптирован для фильмов:

```text
R = свежесть фильма по году выпуска;
F = широта платформенного охвата;
M = рейтинг Rotten Tomatoes как условный показатель качества.
```

Это допустимо как учебная аналитическая адаптация, но важно прямо указывать ограничение: это не классический RFM-анализ в строгом маркетинговом смысле.

Такой подход позволяет сегментировать фильмы по трём измерениям:

- насколько фильм новый;
- насколько широко он представлен на платформах;
- насколько высокую оценку он имеет.

---

## 22. Создание R-сегмента

Сначала создаётся копия таблицы:

```python
movies = df.copy()
```

Это хорошая практика. Копия позволяет выполнять сегментацию, не меняя исходный подготовленный DataFrame.

R-сегмент создаётся по году выпуска:

```python
movies['R_segment'] = pd.qcut(movies['Year'], q=3, labels=['Old','Medium','New'])
```

`pd.qcut()` делит данные на группы примерно одинакового размера по квантилям.

Здесь фильмы делятся на три группы:

```text
Old = старые фильмы;
Medium = фильмы среднего периода;
New = новые фильмы.
```

Результат распределения:

```text
Old: 3176 фильмов
Medium: 3191 фильм
New: 3148 фильмов
```

Группы получились близкими по размеру, потому что использовано квантильное разбиение.

---

## 23. Создание F-сегмента

F-сегмент создаётся на основе количества платформ.

```python
movies['F_segment'] = movies['PlatformCount'].apply(
    lambda x: 'High' if x >= 3 else ('Medium' if x == 2 else 'Low')
)
```

Логика:

```text
High = фильм доступен на 3–4 платформах;
Medium = фильм доступен на 2 платформах;
Low = фильм доступен на 1 платформе.
```

Результат:

```text
Low: 9262 фильма
Medium: 245 фильмов
High: 8 фильмов
```

Этот результат совпадает с логикой ABC-анализа. Он снова показывает, что большинство фильмов имеют узкий платформенный охват.

F-сегмент в данном примере не означает частоту покупок, как в классическом RFM. Здесь он означает широту доступности фильма на платформах.

## 24. Создание M-сегмента

M-сегмент создаётся на основе рейтинга Rotten Tomatoes.

```python
movies['M_segment'] = pd.qcut(
    movies['Rotten Tomatoes'],
    q=3,
    labels=['Low','Medium','High']
)
```

Фильмы делятся на три группы по уровню рейтинга:

```text
Low = низкий рейтинг;
Medium = средний рейтинг;
High = высокий рейтинг.
```

Результат:

```text
Low: 3423 фильма
Medium: 2929 фильмов
High: 3163 фильма
```

Такое разбиение помогает выделить фильмы с относительно высоким и низким качественным показателем внутри датасета.

Ограничение: Rotten Tomatoes — не финансовый показатель. Поэтому буква `M` здесь не означает деньги. Это условная адаптация, где оценка используется как показатель ценности контента.

```python
best_segment = movies[
```

```python
worst_segment = movies[
```

## 28. Ограничения анализа

Любой аналитический вывод должен сопровождаться ограничениями.

В данном примере ограничения такие:

1. **Данные не обязательно отражают текущие каталоги платформ.**

   Стриминговые каталоги постоянно меняются. Фильм может появиться или исчезнуть с платформы.

2. **Возрастной рейтинг неизвестен почти для половины фильмов.**

   Это снижает точность анализа по возрастным категориям.

3. **Rotten Tomatoes используется как единственный показатель качества.**

   Оценка не отражает просмотры, выручку, пользовательскую лояльность, жанровую структуру и локальные предпочтения.

4. **ABC-, XYZ- и RFM-анализ адаптированы под учебную задачу.**

   Это не классическое применение методов. Поэтому результаты нужно интерпретировать как учебную сегментацию, а не как строгий бизнес-рейтинг фильмов.

5. **Платформенный охват не равен популярности фильма.**

   Фильм может быть доступен на одной платформе и при этом быть очень популярным. И наоборот, фильм может быть доступен на нескольких платформах, но иметь низкую востребованность.

## 29. Типовые ошибки в такой аналитической работе

### Ошибка 1. Сразу строить графики без проверки данных

Перед визуализацией нужно проверить структуру таблицы, типы данных и пропуски.

Правильно:

```python
df.info()
df.head()
df.isna().sum()
```

### Ошибка 2. Не преобразовать рейтинг к числу

Если `Rotten Tomatoes` остаётся строкой вида `98/100`, числовой анализ будет некорректным.

Правильно:

```python
df['Rotten Tomatoes'] = df['Rotten Tomatoes'].str.replace('/100', '', regex=False)
df['Rotten Tomatoes'] = pd.to_numeric(df['Rotten Tomatoes'], errors='coerce')
```

### Ошибка 3. Игнорировать пропуски в Age

Если не обработать пропуски, анализ возрастных рейтингов будет неполным.

Правильно:

```python
df['Age'] = df['Age'].fillna('Unknown')
```

### Ошибка 4. Делать слишком сильные выводы по одному показателю

Количество фильмов на платформе не доказывает качество платформы. Рейтинг Rotten Tomatoes не доказывает коммерческий успех фильма.

### Ошибка 5. Не указывать ограничения адаптированных методов

ABC, XYZ и RFM в этом примере используются не в классическом виде. Это нужно явно объяснять в аналитическом отчёте.

## 31. Полный пример кода пайплайна

Ниже приведён объединённый вариант кода, который повторяет основную логику ноутбука.

```python
import pandas as pd
import matplotlib.pyplot as plt

# 1. Загрузка данных
df = pd.read_csv("MoviesOnStreamingPlatforms.csv")

# 2. Первичный осмотр
print(df.info())
print(df.head())
print(df.isna().sum())

# 3. Удаление лишних столбцов
df = df.drop(columns=['Unnamed: 0', 'ID', 'Type'])

# 4. Обработка пропусков Age
df['Age'] = df['Age'].fillna('Unknown')

# 5. Очистка Rotten Tomatoes
df['Rotten Tomatoes'] = df['Rotten Tomatoes'].str.replace('/100', '', regex=False)
df['Rotten Tomatoes'] = pd.to_numeric(df['Rotten Tomatoes'], errors='coerce')

# 6. Заполнение пропусков рейтинга медианой
median_rating = df['Rotten Tomatoes'].median()
df['Rotten Tomatoes'] = df['Rotten Tomatoes'].fillna(median_rating)

# 7. Количество фильмов на платформах
platform_counts = {
    'Netflix': df['Netflix'].sum(),
    'Hulu': df['Hulu'].sum(),
    'Prime Video': df['Prime Video'].sum(),
    'Disney+': df['Disney+'].sum()
}

# 8. Возрастные рейтинги
age_counts = df['Age'].value_counts()

# 9. Десятилетия
df['Decade'] = (df['Year'] // 10) * 10
decade_counts = df['Decade'].value_counts().sort_index()

# 10. Рейтинги
ratings = df['Rotten Tomatoes']

# 11. Охват платформ
df['PlatformCount'] = df[['Netflix','Hulu','Prime Video','Disney+']].sum(axis=1)
platform_count_dist = df['PlatformCount'].value_counts().sort_index()

# 12. ABC-анализ
coverage = df['PlatformCount']
A_films = coverage[coverage >= 3].count()
B_films = coverage[coverage == 2].count()
C_films = coverage[coverage == 1].count()

# 13. XYZ-анализ
X_films = coverage[coverage == 4].count()
Y_films = coverage[(coverage == 2) | (coverage == 3)].count()
Z_films = coverage[coverage == 1].count()

# 14. RFM-анализ
movies = df.copy()
movies['R_segment'] = pd.qcut(movies['Year'], q=3, labels=['Old','Medium','New'])
movies['F_segment'] = movies['PlatformCount'].apply(
    lambda x: 'High' if x >= 3 else ('Medium' if x == 2 else 'Low')
)
movies['M_segment'] = pd.qcut(
    movies['Rotten Tomatoes'],
    q=3,
    labels=['Low','Medium','High']
)

best_segment = movies[
    (movies['R_segment']=='New') &
    (movies['F_segment']=='High') &
    (movies['M_segment']=='High')
]

worst_segment = movies[
    (movies['R_segment']=='Old') &
    (movies['F_segment']=='Low') &
    (movies['M_segment']=='Low')
]

# 15. Вывод ключевых результатов
print("Количество фильмов на платформах:", platform_counts)
print("Возрастные рейтинги:\n", age_counts)
print("Рейтинги Rotten Tomatoes:")
```

## 34. Как улучшить ноутбук

Текущий ноутбук уже показывает рабочую аналитическую логику. Его можно улучшить несколькими способами.

### Улучшение 1. Добавить отдельную ячейку с целью анализа

```text
Цель анализа — изучить структуру каталога фильмов на стриминговых платформах и выявить различия по платформам, возрастным рейтингам, годам выпуска, оценкам и охвату.
```

### Улучшение 2. Добавить проверку пропусков до очистки

```python
df.isna().sum()
```

Так будет видно, почему именно обрабатываются `Age` и `Rotten Tomatoes`.

### Улучшение 3. Не использовать `inplace=True`

В учебных проектах лучше писать явно:

```python
df['Age'] = df['Age'].fillna('Unknown')
```

Так код легче читать и отлаживать.

### Улучшение 4. Сохранять очищенный датасет

```python
df.to_csv("MoviesOnStreamingPlatforms_clean.csv", index=False)
```

## 35. Итог

Выполненный ноутбук показывает полный базовый цикл аналитической работы:

```text
загрузка данных → первичный осмотр → очистка → преобразование признаков → разведочный анализ → сегментация → визуализация → выводы
```

Ключевой результат анализа состоит в том, что каталоги платформ в датасете сильно различаются по объёму, большинство фильмов доступны только на одной платформе, а значительная часть возрастных рейтингов отсутствует. Это означает, что выводы по платформенному охвату достаточно устойчивы внутри данных, а выводы по возрастным категориям требуют осторожности.

Главный учебный смысл пайплайна — показать, что анализ данных не сводится к построению графика. Аналитик должен проверить источник, понять структуру таблицы, очистить признаки, выбрать метод, построить визуализацию, интерпретировать результат и обязательно указать ограничения.
