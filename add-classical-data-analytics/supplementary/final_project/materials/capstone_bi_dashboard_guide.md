# Инструкция по BI-блоку итоговой работы

## Название

Построение BI-дашборда на основе подготовленного датасета

## Цель

Использовать подготовленный файл `bi_dataset.csv` для построения аналитического дашборда, выявления инсайтов и подготовки визуальной части итоговой работы.

BI-блок должен продолжать уже выполненную работу:

```text
ETL → preprocessing → EDA → статистика → взаимосвязи → bi_dataset.csv → BI-дашборд → выводы
```

Дашборд не должен быть набором случайных графиков. Он должен отвечать на аналитические вопросы, которые были сформулированы в notebook.

---

## 1. Что должно быть готово до начала BI-блока

Перед переходом в Power BI, Tableau Public, Yandex DataLens или другую BI-платформу проверьте, что у вас есть файл:

```text
outputs/bi_dataset.csv
```

В этом файле должны быть:

| Тип поля | Примеры | Для чего нужно |
|---|---|---|
| Дата или период | `order_date`, `order_month` | динамика показателей |
| Категории | `region`, `channel`, `category`, `client_segment` | фильтры и разрезы |
| Числовые показатели | `revenue`, `quantity`, `discount`, `rating` | KPI, графики, агрегаты |
| Идентификаторы | `order_id`, `client_id`, `product_id` | подсчёт заказов, клиентов, товаров |
| Расчётные признаки | `revenue_per_item`, `profit`, `profit_margin` | дополнительные метрики |

Если таких полей нет, вернитесь в notebook и доработайте подготовку данных.

## 2. Минимальный состав дашборда

В итоговой работе дашборд должен содержать не меньше одной страницы. Рекомендуемый состав:

### KPI-карточки

Минимум 4–5 карточек:

1. Общая выручка.
2. Количество заказов.
3. Средний чек.
4. Количество клиентов.
5. Доля возвратов или средний рейтинг.

### Графики

Минимум 4 графика:

| Вопрос | График |
|---|---|
| Как менялась выручка во времени? | line chart |
| Какие регионы дают больше выручки? | bar chart |
| Какие категории лидируют? | bar chart |
| Где выше возвраты или ниже рейтинг? | bar chart или table |
| Как распределяется выручка или чек? | histogram, если платформа поддерживает |
| Какие сегменты клиентов важнее? | bar chart или treemap |

### Фильтры

Минимум 2–3 фильтра:

- период;
- регион;
- канал продаж;
- категория;
- сегмент клиента.

# 5. Вариант A. Power BI

## 5.1. Загрузка файла

1. Откройте Power BI Desktop.
2. Выберите загрузку данных из текстового или CSV-файла.
3. Укажите файл:

```text
outputs/bi_dataset.csv
```

4. Проверьте предпросмотр таблицы.
5. Загрузите данные в модель.

## 5.2. Проверка типов данных

После загрузки проверьте:

| Поле | Ожидаемый тип |
|---|---|
| `order_date` | Date |
| `order_month` | Text или Date/Month |
| `revenue` | Decimal number |
| `quantity` | Whole number |
| `discount` | Decimal number |
| `is_returned` | Whole number |
| `region`, `channel`, `category` | Text |

Если тип определился неверно, исправьте его в Power Query или в модели данных.

## 5.3. Рекомендуемые меры

Примеры мер для Power BI:

```DAX
Total Revenue = SUM(bi_dataset[revenue])
```

```DAX
Orders Count = DISTINCTCOUNT(bi_dataset[order_id])
```

```DAX
Average Order Value = DIVIDE([Total Revenue], [Orders Count])
```

```DAX
Return Rate = AVERAGE(bi_dataset[is_returned])
```

```DAX
Average Rating = AVERAGE(bi_dataset[rating])
```

## 5.4. Рекомендуемые визуализации

| Объект | Поля |
|---|---|
| KPI: Total Revenue | `Total Revenue` |
| KPI: Orders Count | `Orders Count` |
| KPI: Average Order Value | `Average Order Value` |
| Line chart | `order_month` → `Total Revenue` |
| Bar chart by region | `region` → `Total Revenue` |
| Bar chart by category | `category` → `Total Revenue` |
| Bar chart by channel | `channel` → `Orders Count` или `Total Revenue` |
| Table | `region`, `category`, `Total Revenue`, `Return Rate`, `Average Rating` |

## 5.5. Публикация

Если требуется поделиться результатом, отчёт можно опубликовать из Power BI Desktop в Power BI service. Перед публикацией проверьте, что в отчёте нет персональных, конфиденциальных или закрытых данных.

## 11. Типовые ошибки

| Ошибка | Почему это проблема | Как исправить |
|---|---|---|
| В BI загружен грязный исходный CSV | Дашборд показывает некорректные метрики | Загружать `outputs/bi_dataset.csv` |
| Дата распознана как текст | Не строится корректная динамика | Исправить тип поля на Date |
| Все показатели отображаются как текст | Нельзя считать суммы и средние | Исправить типы данных |
| Нет фильтров | Дашборд нельзя исследовать интерактивно | Добавить фильтры по периоду и категориям |
| Слишком много графиков | Пользователь теряет основной вывод | Оставить только графики, отвечающие на вопросы |
| Графики без подписей | Непонятно, что показано | Добавить заголовки и понятные названия |
| Нет выводов | BI-блок не превращается в аналитику | Добавить 3–5 инсайтов |
| Публично опубликованы закрытые данные | Нарушение безопасности | Использовать только открытые или обезличенные данные |
| KPI считаются по строкам, а не по заказам | Метрики искажены | Использовать `DISTINCTCOUNT(order_id)` |
| Средний чек рассчитан неверно | Ошибка бизнес-логики | Делить выручку на количество заказов |
