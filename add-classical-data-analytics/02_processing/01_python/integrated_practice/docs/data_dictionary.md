# Словарь данных

В исходных файлах используются технические имена полей на английском языке. Это нужно, чтобы код Python, pandas и SQL-запросы работали одинаково у всех слушателей. Для чтения и обсуждения ниже добавлены русские названия полей.

## sales.csv — продажи и заказы

| Техническое поле | Русское название | Тип | Описание |
|---|---|---|---|
| `order_id` | Номер заказа | text | Идентификатор заказа |
| `order_date` | Дата заказа | text/date | Дата заказа. В исходных данных может быть строкой или некорректным значением |
| `client_id` | Код клиента | text | Идентификатор клиента |
| `product_id` | Код товара | text | Идентификатор товара |
| `region_id` | Код региона | text | Идентификатор региона |
| `channel` | Канал продаж | text | Канал, через который была оформлена продажа |
| `quantity` | Количество | integer | Количество единиц товара |
| `unit_price` | Цена за единицу | real | Цена одной единицы товара |
| `discount` | Скидка | real | Скидка от 0 до 1. Например, 0.10 означает 10% |

## products.xlsx — справочник товаров

| Техническое поле | Русское название | Тип | Описание |
|---|---|---|---|
| `product_id` | Код товара | text | Идентификатор товара |
| `product_name` | Название товара | text | Название товара |
| `category` | Категория | text | Категория товара |
| `cost` | Себестоимость | real | Себестоимость единицы товара |

## regions.json — справочник регионов

| Техническое поле | Русское название | Тип | Описание |
|---|---|---|---|
| `region_id` | Код региона | text | Идентификатор региона |
| `region_name` | Регион | text | Название региона |
| `macro_region` | Макрорегион | text | Крупная территориальная группа |

## clients.csv — справочник клиентов

| Техническое поле | Русское название | Тип | Описание |
|---|---|---|---|
| `client_id` | Код клиента | text | Идентификатор клиента |
| `segment` | Сегмент клиента | text | Клиентский сегмент |
| `registration_date` | Дата регистрации | text/date | Дата регистрации клиента |
| `loyalty_level` | Уровень лояльности | text | Уровень лояльности клиента |

## Поля, которые создаются в notebook

| Техническое поле | Русское название | Как появляется |
|---|---|---|
| `revenue` | Выручка | `quantity * unit_price * (1 - discount)` |
| `order_month` | Месяц заказа | выделяется из `order_date` |
| `is_discounted` | Есть скидка | `discount > 0` |
| `discount_group` | Группа скидки | создаётся по диапазонам скидки |
| `orders_count` | Количество заказов | количество уникальных `order_id` |
| `clients_count` | Количество клиентов | количество уникальных `client_id` |
| `total_revenue` | Общая выручка | сумма `revenue` |
| `avg_order_revenue` | Средняя выручка на заказ | среднее значение `revenue` |
| `avg_discount` | Средняя скидка | среднее значение `discount` |

## Связи между таблицами

```text
sales.product_id -> products.product_id
sales.region_id  -> regions.region_id
sales.client_id  -> clients.client_id
```

## Почему не переименовываем исходные столбцы полностью на русский

Технические имена полей лучше оставить на английском, потому что они используются в Python-коде, SQL-запросах и SQLite-базе. Вместо полного переименования в исходных данных в notebook добавлены русские подписи для вывода таблиц. Так слушателю легче читать результат, а код остаётся устойчивым.
