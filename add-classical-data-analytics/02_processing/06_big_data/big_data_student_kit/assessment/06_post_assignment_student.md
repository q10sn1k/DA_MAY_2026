# Самостоятельная работа
## «Подготовка масштабируемой аналитической витрины событий»

## Цель

Закрепить полный цикл работы с крупным набором событий: проверка качества, преобразование формата, SQL-агрегация, партиционирование, визуализация и формулирование выводов.

## Исходные данные

Создайте стандартный набор на 1 000 000 строк:

```bash
python scripts/generate_events.py --rows 1000000 --output data/raw/events_standard.csv --seed 20260803
```

Разрешается использовать набор `events_lite.csv`, если устройство не позволяет обработать стандартную версию. В отчёте укажите фактический файл и число строк.

## Задание

### 1. Проверка исходных данных

Определите:

- количество строк;
- временной диапазон;
- число уникальных пользователей и сессий;
- пропуски в ключевых полях;
- повторяющиеся `event_id`;
- отрицательные значения цены, количества и времени ответа;
- распределение событий по типам.

### 2. Очистка

Зафиксируйте правила обработки:

- строк без `event_id`;
- повторяющихся событий;
- пропущенного региона;
- отрицательных значений;
- пустых числовых полей.

Сохраните число строк до и после очистки.

### 3. Формат хранения

Создайте очищенный `events.parquet` со сжатием. Сравните размеры исходного CSV и Parquet. Не делайте вывод о скорости только по одному измерению.

### 4. Аналитические расчёты

Рассчитайте:

1. Число событий и пользователей по типам событий.
2. Сумму покупок и число покупателей по регионам.
3. Пользовательскую конверсию из просмотра в покупку.
4. Дневное количество событий.
5. Среднее время ответа по устройствам.
6. Долю каждого устройства в событиях покупки.
7. День максимальной активности и состав событий в этот день.

### 5. Партиционирование

Создайте партиционированный набор по `event_date` либо по месяцу, если расширите период генерации. Объясните выбор ключа. Покажите пример запроса, который использует фильтр по ключу партиции.

### 6. Аналитическая витрина

Сформируйте файл `daily_region_device_metrics.parquet` на уровне:

```text
event_date × region × device
```

Минимальные показатели:

- `events_count`;
- `users_count`;
- `sessions_count`;
- `average_response_ms`;
- `purchase_events`;
- `gross_value`.

### 7. Визуализация

Постройте минимум три графика:

- динамика событий по дням;
- сумма покупок по регионам;
- среднее время ответа по устройствам или динамика выбранного региона.

Каждый график должен иметь заголовок, подписи осей и понятную агрегацию.

### 8. Аналитические выводы

Сформулируйте не менее трёх выводов. Каждый вывод должен содержать:

1. наблюдение;
2. числовое подтверждение;
3. интерпретацию;
4. ограничение или следующий шаг.

Отдельно укажите минимум два ограничения анализа.
