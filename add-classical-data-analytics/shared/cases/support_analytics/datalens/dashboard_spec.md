# Спецификация дашборда аналитики поддержки

## Назначение

Дашборд объединяет операционную ситуацию, прогноз нагрузки, риск нарушения SLA и качество данных. Источники имеют разную гранулярность, поэтому рекомендуется создать отдельные датасеты и страницы, а не выполнять физический JOIN всех CSV в одну таблицу.

## Источники

| Датасет | Файл | Гранулярность |
|---|---|---|
| Операции и риск | `outputs/bi_export.csv` | одно обращение |
| Прогноз и мощность | `outputs/forecast_scenarios.csv` | дата × сценарий |
| Validation gate | `outputs/data_validation_gate.csv` | одна проверка |
| Качество загрузок | `outputs/load_quality_summary.csv` | один источник |

## Страница 1. Операционная ситуация

| Объект | Тип | Поля | Аналитический вопрос |
|---|---|---|---|
| Обращения | Индикатор | `SUM([tickets_count])` | Каков объём потока? |
| Доля SLA | Индикатор | вычисляемое поле | Какова доля нарушений? |
| Первый ответ | Индикатор | `AVG([first_response_min])` | Как быстро отвечаем? |
| Динамика | Линейный график | `created_date`, обращения | Как меняется нагрузка? |
| Карта регионов | Карта, точки | `region_point`, размер = обращения, цвет = SLA rate | Где объём и риск максимальны? |
| Риск по командам | Линейчатая диаграмма | `team_name`, SLA rate | Какие команды требуют внимания? |
| Каналы | Столбчатая диаграмма | `channel`, обращения | Откуда поступает поток? |

Селекторы: период, макрорегион, город, команда, канал, категория, приоритет.

## Страница 2. Прогноз и мощность

Источник: `forecast_scenarios.csv`.

| Объект | Тип | Поля |
|---|---|---|
| Прогноз и интервал | Линейный график | `date`, `forecast`, `lower_80`, `upper_80` |
| Потребность в операторах | Линейный график | `date`, `required_agents`, `available_agents` |
| Максимальный дефицит | Индикатор | `MAX([capacity_gap])` |
| Дни дефицита | Индикатор | вычисляемое поле |
| Сценарий | Селектор | `scenario` |

Селектор `scenario` связывается только с объектами этой страницы. Для временных графиков включается Navigator.

## Страница 3. Риск SLA

Источник: `bi_export.csv`.

| Объект | Тип | Поля |
|---|---|---|
| Высокорисковые обращения | Индикатор | `SUM([risk_class])` |
| Средняя вероятность | Индикатор | `AVG([risk_probability])` |
| Очередь приоритетов | Таблица | ticket, team, priority, probability |
| Распределение риска | Гистограмма | `risk_probability` |
| Риск по сегментам | Линейчатая диаграмма | `customer_segment`, средняя вероятность |
| Риск по кластерам | Линейчатая диаграмма | `cluster_name`, SLA rate |

Таблица сортируется по `risk_probability` по убыванию и по умолчанию фильтруется `risk_class = 1`.

## Страница 4. Качество данных

Используются два датасета: validation gate и качество загрузок.

| Объект | Тип | Поля |
|---|---|---|
| Критические FAIL | Индикатор | вычисляемое поле |
| Проверки по статусу | Столбчатая диаграмма | `status`, количество проверок |
| Таблица нарушений | Таблица | stage, dataset, check, severity, status, details |
| Свежесть источников | Таблица | source, freshness, failure rate |
| Отклонённые строки | Столбчатая диаграмма | source, rejected rows |

## Связи и ограничения

- Селекторы страницы 1 связываются только с операционными чартами.
- Селектор сценария связывается только с прогнозным датасетом.
- Не создавайте связь по полям, которые имеют разную семантику или гранулярность.
- Доля SLA считается как отношение сумм, а не среднее строковых процентов.
- Порог риска должен соответствовать результату notebook `04b`.
- Права доступа проверяются на отдельном тестовом пользователе.
